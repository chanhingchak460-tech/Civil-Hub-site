感測器、小型電腦、網絡與模型在真實限制下協同運作。這門科目與其說講最聰明的演算法，不如說講延遲、能源、頻寬與新鮮度，以及這些取捨對互聯基礎設施的意義。

進度只儲存在此瀏覽器。

01重點在迴路，不在裝置

AIoT 將推論放在數據產生的地方附近。系統以換能器感測，在微控制器上調理訊號，經網絡傳送，並根據決策採取行動。

它與普通 IoT 的分別，在於由模型作出決策，而且往往就在裝置本身進行。設計問題從來不只是準確度：而是每單位能源、延遲與頻寬的準確度。

以毫秒級回報的橋樑應變感測器，與每小時醒來一次的土壤探針，解決的是不同的問題。

Nyquist 取樣規則
\[f_s > 2 f_{\max}\]
取樣頻率須高於關注最高頻率的兩倍，否則快速振動會混疊成假的慢波

02感測、取樣與微控制器

感測器將物理量轉換為電訊號，而 ADC 以固定的取樣率將其轉為數字。真實讀數帶有雜訊與漂移，因此要對照參考值進行校準並濾波，同時記住每個濾波器都會增加延遲。

微控制器提供 GPIO 腳位、計時器，以及供本地晶片使用的 I²C 和 SPI 等匯流排，而且必須以工作週期方式運作：無線電與感測主導功率預算，因此在取樣之間休眠，才能讓電池維持數年。

ADC 解析度
\[\Delta V = \frac{V_{\mathrm{ref}}}{2^n}\]
n 位元轉換器的最小電壓步階；真實讀數通常涵蓋數個步階

03網絡選擇

沒有單一無線電技術適合所有部署。在連結層之上，MQTT 是常用的訊息模式：裝置向代理發佈到諸如 site/42/temperature 的主題，訂閱者則接收該訊息。

QoS 等級 0、1 和 2 在重複訊息與傳遞保證之間取捨，而保留訊息可避免遲來的訂閱者看到過時狀態。

以 MQTT 發佈讀數
client.publish('site/42/strain', payload, qos=1) client.subscribe('site/42/command')
qos=1 提供至少一次傳遞，因此處理程序必須能容忍重複訊息
典型 AIoT 部署的無線電選項
無線電典型範圍數據速率功率典型用途
Wi-Fi數十米高高攝影機、閘道器、室內感測器
BLE約 10 米低極低穿戴裝置、信標、手機連結
LoRaWAN2–15 公里極低極低土壤探針、鄉郊儀錶
NB-IoT數公里低低公用事業儀錶、街道設施

04MQTT 以外的協定

MQTT 並非傳送位元組的唯一方式。CoAP 將 HTTP 的請求–回應模型精簡到 UDP 上，供受限節點使用，具備可確認訊息與 observe 模式作伺服器推送；它適合位於閘道器後方的電池感測器，而非頻繁通訊的網頁應用。

純 HTTP/REST 易於除錯與整合，但每則訊息較冗長；WebSockets 為即時儀表板維持持久通道；AMQP 為大量閘道器加入企業級路由。

按限制而非習慣來選擇：負載與標頭開銷、連線狀態、傳遞保證，以及網絡是端到端 IP 還是需要閘道器轉譯。假設 TCP 永遠在線的協定，並不適合每小時醒來一次的節點。

訊息協定比較
協定傳輸模式最適合
MQTTTCP按主題發佈–訂閱從眾多裝置到眾多應用的遙測
CoAPUDP請求–回應、observe受限電池節點、本地探索
HTTP/RESTTCP請求–回應雲端 API 與簡單整合
WebSocketTCP持久雙向即時儀表板與遙距指令

05邊緣還是雲端

推論可在裝置、閘道器或雲端執行。推得越近，延遲與頻寬越低，但模型大小與能源受限。端到端延遲是各階段之和，而最慢的階段主導整體。

模型壓縮讓邊緣推論變得可行：量化以 8 位元而非 32 位元儲存權重，剪枝移除小權重，兩者都付出少許準確度代價。應將此選擇視為取捨曲線，而非口號。

端到端延遲
\[L = t_{\mathrm{sense}} + t_{\mathrm{queue}} + t_{\mathrm{compute}} + t_{\mathrm{network}}\]
量度每個階段；優化錯誤的階段毫無得益
服務容量
\[C = \frac{1}{t_{\mathrm{service}}}\]
當服務時間以秒計，單位為每秒樣本數

06學習型控制器：從規則到梯度

裝置上的 AI 往往是學習型控制器，而非視覺模型。基於規則的層以固定閾值切換；學習層從特徵計算線性分數，並以 sigmoid 函數轉為機率。

訓練透過下降交叉熵損失的梯度來找出權重，該損失對自信的錯誤懲罰遠大於猶豫的錯誤。

工作流程與數學同樣重要：從運作中的控制器收集有標籤的行為，在執行時抽取相同的特徵，離線訓練，然後在線運行小型模型。由於模型學習的是決策模式而非物理，它重現教師的行為卻不理解房間——這正是訓練數據必須涵蓋邊緣情況的原因。

線性分數
\[s = w_1 x_1 + w_2 x_2 + w_3 x_3 + b\]
特徵 x 由近期讀數計算；s = 0 為決策邊界
Sigmoid 機率
\[p = \frac{1}{1 + e^{-s}}\]
p 為正類別的預測機率
交叉熵損失
\[l = -[y\ln p + (1-y)\ln(1-p)]\]
y ∈ {0, 1} 為標籤；自信的錯誤答案代價為大損失
梯度更新步驟
\[w \leftarrow w - \eta (p - y) x\]
η 為學習率；每個訓練樣本一小步

07串流、隊列與新鮮度

感測數據持續到達，因此 AIoT 系統是一個排隊系統。當到達率接近服務率，等待時間會爆炸：在 80% 使用率下，隊列已比 50% 時長四倍。

准入控制決定隊列滿時丟棄哪些樣本，這是系統在過載下自我保護的方式。另一個有用的量度是資訊年齡，即最新已處理樣本的年齡。對過時數據作出非常準確的推論，比得上一個粗略但即時的答案更差。

使用率
\[\rho = \lambda t_{\mathrm{service}}\]
ρ 必須保持在 1 以下，隊列才穩定
Little 定律
\[L = \lambda W\]
系統中平均項目數等於到達率乘以系統中平均時間
M/M/1 隊列的平均等待
\[L_q = \frac{\rho^2}{1 - \rho}\]
當 ρ 趨近 1 時發散

08小型核心上的實時排程

必須按時取樣、傳輸和推論的邊緣節點是一個實時系統：每個任務有週期與最壞情況執行時間，以及絕不可錯過的截止時間。第一步檢查是使用率，即每個任務的執行時間除以週期之總和。

單調速率將最短週期的任務賦予最高優先級，在固定優先級方案中可證明為最優；最早截止時間優先按剩餘截止時間排序，可使單一處理器忙至滿使用率。

題目通常給出任務表並問該集合是否可排程：計算使用率，與界限比較，對單調速率還須檢查每個任務的回應時間。在基礎設施監測中錯過截止時間意味著漏掉警報，因此排程是設計約束，而非事後補救。

CPU 使用率
\[U = \sum \frac{C_i}{T_i}\]
C_i 執行時間，T_i 週期；U ≤ 1 對任何排程器都是必要條件
單調速率界限
\[U \le n\,(2^{1/n} - 1)\]
n 個任務在單調速率排程下的充分條件；趨向 ln 2 ≈ 0.693
EDF 界限
\[U \le 1\]
單一處理器上最早截止時間優先的充分必要條件

09數碼分身與智慧基礎設施

數碼分身是由感測數據保持最新的模型，用於監測、模擬與預測。在基礎設施上，它表現為橋樑的結構健康監測、供水網絡的漏水偵測，或建築物的佔用控制。

其價值取決於迴路是否閉合：預測軸承故障的模型，除非維修系統據此行動，否則毫無用處。分身亦繼承其數據的所有弱點——漂移、缺失讀數，以及翻新後改變的基線。

10設計內建的保安與私隱

每個聯網感測器都是攻擊面。常見的失效包括預設密碼、未簽署的韌體、未加密的連結，以及無法修補已安裝的裝置。

實際的防禦是裝置身份與雙向認證、連結上的 TLS、簽署的韌體更新與網絡分段，使受入侵的感測器無法觸及控制系統。

私隱也是設計約束：收集最少數據、在邊緣聚合，並將個人資料排除在不需要的地方之外。一個洩露家中無人的智慧水錶是私隱問題，不僅僅是公用事業問題。

邊緣的數據最小化
send aggregate, not raw: (mean, count, timestamp)
離開裝置的位元組與個人資訊更少

11虛擬感測與隱藏狀態

並非所有值得知道的事物都有專用感測器。虛擬感測透過模型從可觀測訊號推斷隱藏量：攝影機影像得出深度，Wi-Fi 訊號強度指紋得出室內位置，智能手機的慣性讀數得出步行速度。模式總是可觀測訊號 → 模型 → 隱藏狀態。

虛擬感測器降低硬件成本，並可覆蓋物理探針無法到達的地方，但它們繼承模型誤差與漂移，因此需要定期對照地面真值重新校準。應將其輸出視為帶置信度的估計，並保留後備方案：當模型不確定時，拒絕行動而非錯誤行動。

計算示例

邊緣能否跟上串流？

一個振動感測器每秒產生 20 個樣本。邊緣模型每個樣本需時 40 ms。雲端模型需 80 ms 運算加上 50 ms 網絡時間。求每個選項的服務容量、邊緣使用率，以及若邊緣隊列為 M/M/1 系統時的平均等待時間。哪個配置可行？

  1. 邊緣容量 = 1 / 0.040 = 每秒 25 個樣本。雲端容量 = 1 / 0.130 = 每秒 7.7 個樣本。
  2. 以 λ = 每秒 20 個樣本計算，雲端使用率為 20 × 0.130 = 2.6，超過 1，因此雲端隊列無限增長，不存在平均延遲。
  3. 邊緣使用率為 ρ = 20 × 0.040 = 0.8，穩定但負載沉重。
  4. 對 M/M/1 隊列，L_q = ρ²/(1 − ρ) = 0.64/0.20 = 3.2 個樣本平均等待。
  5. 平均等待時間 = L_q / λ = 3.2 / 20 = 0.16 s，因此系統中平均時間約為 0.16 + 0.04 = 0.20 s。
Answer在每秒 20 個樣本下，只有邊緣配置穩定。雲端無法跟上，而邊緣給出約 0.20 s 的平均決策年齡，對振動監測可接受，但若感測率上升則需要卸載。

應試方法

  • 在提出架構前先指出瓶頸階段；延遲與能源題目按取捨評分，而非產品名稱。
  • 在排隊題目中，先計算 ρ = λ t_service：若 ρ ≥ 1，隊列不穩定，不存在平均延遲。
  • 在命名協定前，先將範圍、數據速率與功率配合應用，並說明替代方案為何失利。
  • 當出現任務表時，先計算 U = Σ C_i/T_i，然後套用單調速率或 EDF 界限，並說明截止時間等於週期的假設。
