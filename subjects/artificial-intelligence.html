Artificial intelligence is the engineering of systems that perceive, reason and learn. This page covers search, knowledge representation, learning, neural networks, generative models and how to evaluate them honestly.

01What AI asks of an engineer

AI is not one algorithm but a family of methods for acting under uncertainty. The classical framing separates perception, reasoning, learning and action, and asks what the system must decide, what it can observe and what being wrong would cost.

Most deployed AI is narrow: excellent at one task and unable to transfer. That is the design scope rather than a fault, and writing it down is the first engineering decision.

02Search: from a goal to a path

Many problems are posed as a state space: states, actions, a start, a goal and a cost per step.

  • Breadth-first search finds the fewest steps.
  • Depth-first saves memory but can wander.
  • Uniform-cost search expands the cheapest prefix first.
  • A* adds a heuristic estimate of the remaining cost.

If the heuristic never overestimates — if it is admissible — A* returns a least-cost path without exploring everything. The heuristic is the whole design: too weak is nearly blind, too optimistic loses optimality.

A* evaluation function
\[f(n) = g(n) + h(n)\]
g is the cost from the start, h the estimated cost to the goal

03Knowledge representation

A reasoning system needs a model of the world it can manipulate.

  • Logic represents facts and rules and derives conclusions mechanically.
  • Frames and semantic networks group attributes around objects.
  • Ontologies and knowledge graphs fix a shared vocabulary so different systems mean the same thing by the same term.

Engineering knowledge is messy and uncertain. Probabilistic models, rules carrying confidence and explicit assumptions record what is not known, which matters as much as what is.

04Machine learning: learning a mapping

A supervised model learns a mapping from features to labels using examples. Data are split into training, validation and test sets; the test set is touched once, at the end, to estimate generalisation.

A model that fits its training data but fails on new data is overfitting. The remedy is discipline, not complexity: representative data, regularisation, simpler models and a validation loop that does not quietly tune the test score. Always report a naive baseline.

05Neural networks and deep learning

A single artificial neuron computes a weighted sum of its inputs plus a bias and passes the result through a non-linear activation function. Stacking layers represents complicated relationships.

Training adjusts the weights to reduce a loss, typically by gradient descent with backpropagation supplying the gradient for every weight.

Depth helps because early layers learn general features and later layers combine them. It also makes optimisation harder, data demand greater and behaviour less interpretable.

Artificial neuron
\[a = \varphi\left(\sum_i w_i x_i + b\right)\]
φ is a non-linear activation such as ReLU or sigmoid
Gradient descent update
\[w \leftarrow w - \eta \frac{\partial L}{\partial w}\]
η is the learning rate; the gradient comes from backpropagation

06Generative models

A generative model learns the distribution of its training data and produces new samples.

  • Large language models predict the next token from the preceding ones, so generation is repeated prediction.
  • Diffusion models add noise to data in training and learn to reverse that process when sampling.

Generation is sampling, not recall. That explains the fluency and the hallucination: a plausible continuation is not a true one.

Autoregressive generation
\[p(x_1, \ldots, x_T) = \prod_{t=1}^{T} p(x_t \mid x_{<t})\]
the probability of a sequence is built one token at a time

07Evaluation is part of the design

A model is only as good as the evidence used to judge it. Split data honestly, keep a hold-out set, and choose metrics that match the cost of error.

In defect detection, precision asks how many flagged defects were real, while recall asks how many real defects were caught; a high-accuracy model that always says no defect is useless.

Evaluation also covers latency, robustness to shifted inputs, calibration and test-data leakage. Generative output needs rubric-based human assessment, with criteria fixed in advance.

Evaluation metrics and the failure each one can hide
MetricQuestion answeredFailure hidden
AccuracyHow many cases were labelled correctly overallFailure on a rare class
PrecisionOf the cases flagged, how many were rightMissed true positives
RecallOf the true cases, how many were foundFalse alarms
F1 scoreBalance of precision and recallTrue negatives, and the cost of each error
CalibrationDo predicted probabilities match outcomesConfident answers that are wrong

08Responsible AI and professional judgement

Deploying AI is a professional act with consequences.

  • Accountability stays with the engineer even when a model made the suggestion.
  • Bias in training data becomes bias in decisions.
  • Personal data need a lawful basis.
  • Generated content may infringe rights or be mistaken for evidence.

The controls are familiar from safety engineering: document the data and model, test on the population that will use it, keep a human decision point for high-stakes output, monitor after deployment, and be able to explain and withdraw the system.

Expected cost of a decision
\[E[\text{cost}] = p_{fp} C_{fp} + p_{fn} C_{fn}\]
the decision threshold should reflect the relative cost of the two errors

09Prompt engineering

A language model's output quality is set by its prompt: the instruction, context and examples given before generation.

  • Effective prompts are specific about the task and the audience.
  • Provide data and examples rather than vague hints.
  • Name the desired output format.
  • Describe what to do instead of what not to do.
  • Giving the model a role — reviewer, tutor, site engineer — frames the vocabulary it will use.

Chain-of-thought prompting asks the model to work through intermediate steps before answering, which measurably improves arithmetic and multi-step reasoning. Temperature controls sampling randomness: low values repeat the most probable token and give deterministic, safe output; high values trade fluency for variety and hallucination.

Temperature-scaled softmax
\[p(w_i) = \frac{e^{z_i/T}}{\sum_j e^{z_j/T}}\]
T → 0 picks the most likely token; larger T flattens the distribution

10Generative media: image, audio and video

Diffusion models generate images by learning to reverse a process that gradually adds noise: sampling starts from pure noise and denoises step by step, guided by a text description or other conditioning. Audio models apply the same idea to waveforms or spectrograms for speech and music, and video generation must additionally keep consecutive frames consistent.

Treat generated media as evidence-free by default: synthetic faces and voices are cheap to produce and hard for people to detect. Verification relies on provenance — watermarks, signed metadata and detection tools — and on process controls such as labelling, not on asking viewers to spot the fake.

Diffusion training objective
\[L = \mathbb{E}\left\lVert \varepsilon - \varepsilon_\theta(x_t, t) \right\rVert^2\]
the network learns to predict the noise ε added to a corrupted sample

11Code generation and its limits

Large language models write code from natural language, partial programs or execution examples, and coding assistants combine tab completion with chat-based edits.

  • Strong at boilerplate, regular expressions and test scaffolding.
  • Weak where the context is long, the library is obscure or the correct answer depends on facts the model never saw.

pass@k is the standard measure: the probability that at least one of k generated attempts passes all the provided tests. Evaluation is therefore as good as the test suite — code that compiles can still be wrong. Review generated code exactly like human code: run the tests, check for hallucinated library functions, and keep a human owner for anything that touches safety.

Pass@k
\[\text{pass@}k = 1 - (1 - p)^k\]
p is the chance one sample passes; more attempts raise the odds but cost compute
Hallucinated APIs Generated code can call functions or libraries that do not exist; run it in a test harness before trusting it, and never paste credentials or private data into a public model.

Key terms

Admissible heuristic
An estimate of remaining cost that never exceeds the true cost, which keeps A* search optimal.
Overfitting
Fitting the training data so closely that performance on new, unseen data falls.
Precision
The proportion of cases flagged by a model that are genuinely positive.
Hallucination
Fluent, plausible generated content that is nevertheless unsupported or false.
Diffusion model
A generative model that learns to reverse a gradual noising process to produce samples.
Generalisation
Performance on data the model has not been trained on, estimated with a held-out test set.
Prompt engineering
Designing instructions, context and examples so that a language model produces the desired output.
Temperature
A sampling parameter that scales token probabilities; low values are deterministic, high values more varied.
Worked example

Reading a defect detector's confusion matrix

A vision model is tested on 500 inspection images. It correctly flags 92 defective panels and correctly clears 362 sound ones. It wrongly flags 18 sound panels and misses 28 defective panels. Calculate accuracy, precision and recall, and say why accuracy on its own is misleading.

  1. Confusion matrix: TP = 92, FP = 18, FN = 28, TN = 362, which totals 500 images.
  2. Accuracy = (TP + TN) / total = (92 + 362) / 500 = 454 / 500 = 0.908, or 90.8 per cent.
  3. Precision = TP / (TP + FP) = 92 / 110 = 0.836, or 83.6 per cent.
  4. Recall = TP / (TP + FN) = 92 / 120 = 0.767, or 76.7 per cent.
  5. F1 = 2PR / (P + R) = 2 × 0.836 × 0.767 / (1.603) = 0.80.
  6. Baseline check: a model that always says sound scores 380 / 500 = 76 per cent accuracy while detecting nothing, so accuracy alone flatters a model on an imbalanced set.
AnswerAccuracy is 90.8 per cent, precision 83.6 per cent and recall 76.7 per cent, with an F1 of about 0.80. About one defective panel in four is missed, so for a safety-related inspection task the threshold should be moved to raise recall, and the cost of false alarms weighed against the missed-defect cost.

Exam method

  • Before discussing any search algorithm, write down the state space, the actions and the cost of a step.
  • Quote precision and recall together with the dataset and the split; neither number means anything alone.
  • In responsible-AI questions, keep a named human accountable and state where the oversight step sits.
  • Fix the evaluation rubric before generating anything, and score generated output against it blind; an impression of quality is not a metric.
