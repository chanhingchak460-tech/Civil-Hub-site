01AI가 엔지니어에게 요구하는 것

AI는 하나의 알고리즘이 아니라 불확실성 속에서 행동하기 위한 방법들의 집합이다. 고전적인 틀은 인지, 추론, 학습, 행동을 구분하고, 시스템이 무엇을 결정해야 하는지, 무엇을 관찰할 수 있는지, 틀렸을 때 어떤 비용이 드는지를 묻는다.

배포된 AI의 대부분은 좁은(narrow) AI다. 한 가지 작업에는 뛰어나지만 전이하지 못한다. 이는 결함이 아니라 설계 범위이며, 이를 문서로 남기는 것이 첫 번째 공학적 결정이다.

02탐색: 목표에서 경로로

많은 문제는 상태 공간으로 제시된다. 상태, 행동, 시작점, 목표, 그리고 단계당 비용이 그것이다.

  • 너비 우선 탐색은 최소 단계 수를 찾는다.
  • 깊이 우선 탐색은 메모리를 절약하지만 헤맬 수 있다.
  • 균일 비용 탐색은 가장 저렴한 접두부를 먼저 확장한다.
  • A*는 남은 비용에 대한 휴리스틱 추정치를 더한다.

휴리스틱이 결코 과대평가하지 않는다면, 즉 허용 가능(admissible)하다면, A*는 모든 것을 탐색하지 않고도 최소 비용 경로를 반환한다. 휴리스틱이 곧 설계의 전부다. 너무 약하면 거의 장님과 같고, 너무 낙관적이면 최적성을 잃는다.

A* 평가 함수
\[f(n) = g(n) + h(n)\]
g는 시작점으로부터의 비용, h는 목표까지의 추정 비용

03지식 표현

추론 시스템은 조작할 수 있는 세계의 모델이 필요하다.

  • 논리는 사실과 규칙을 표현하고 결론을 기계적으로 도출한다.
  • 프레임과 의미망은 객체를 중심으로 속성을 묶는다.
  • 온톨로지와 지식 그래프는 공유 어휘를 정하여 서로 다른 시스템이 같은 용어로 같은 의미를 갖게 한다.

공학 지식은 지저분하고 불확실하다. 확률적 모델, 신뢰도를 지닌 규칙, 명시적 가정은 알려지지 않은 것을 기록하며, 이는 아는 것만큼이나 중요하다.

04머신러닝: 매핑 학습

지도 학습 모델은 예제를 사용하여 특징에서 레이블로의 매핑을 학습한다. 데이터는 훈련, 검증, 테스트 세트로 나뉘며, 테스트 세트는 일반화를 추정하기 위해 마지막에 한 번만 사용된다.

훈련 데이터에는 맞지만 새 데이터에서 실패하는 모델은 과적합이다. 해결책은 복잡성이 아니라 규율이다. 대표성 있는 데이터, 정규화, 더 단순한 모델, 그리고 테스트 점수를 몰래 조정하지 않는 검증 루프가 필요하다. 항상 단순 기준선(naive baseline)을 보고하라.

05신경망과 딥러닝

단일 인공 뉴런은 입력의 가중 합에 편향을 더하고 그 결과를 비선형 활성화 함수에 통과시킨다. 층을 쌓으면 복잡한 관계를 표현할 수 있다.

훈련은 손실을 줄이도록 가중치를 조정하며, 일반적으로 역전파가 모든 가중치의 기울기를 제공하는 경사 하강법을 사용한다.

깊이는 초기 층이 일반적인 특징을 학습하고 후기 층이 이를 결합하기 때문에 도움이 된다. 동시에 최적화를 어렵게 하고, 데이터 요구를 키우며, 동작을 덜 해석 가능하게 만든다.

인공 뉴런
\[a = \varphi\left(\sum_i w_i x_i + b\right)\]
φ는 ReLU나 시그모이드 같은 비선형 활성화 함수
경사 하강법 갱신
\[w \leftarrow w - \eta \frac{\partial L}{\partial w}\]
η는 학습률이며, 기울기는 역전파에서 나온다

06생성 모델

생성 모델은 훈련 데이터의 분포를 학습하고 새로운 샘플을 생성한다.

  • 대규모 언어 모델은 선행 토큰으로부터 다음 토큰을 예측하므로, 생성은 반복된 예측이다.
  • 확산(diffusion) 모델은 훈련 중 데이터에 노이즈를 더하고, 샘플링 시 그 과정을 역으로 학습한다.

생성은 회상이 아니라 샘플링이다. 이것이 유창함과 환각(hallucination)을 설명한다. 그럴듯한 연속은 참인 연속이 아니다.

자기회귀 생성
\[p(x_1, \ldots, x_T) = \prod_{t=1}^{T} p(x_t \mid x_{<t})\]
시퀀스의 확률은 한 번에 한 토큰씩 구성된다

07평가는 설계의 일부

모델은 그것을 판단하는 데 사용된 증거만큼만 좋다. 데이터를 정직하게 분할하고, 홀드아웃 세트를 유지하며, 오류 비용에 맞는 지표를 선택하라.

결함 탐지에서 정밀도는 표시된 결함 중 실제 결함이 얼마나 되는지를 묻고, 재현율은 실제 결함 중 얼마나 발견되었는지를 묻는다. 항상 결함 없음이라고 말하는 높은 정확도의 모델은 쓸모없다.

평가는 지연 시간, 입력 변화에 대한 견고성, 보정(calibration), 테스트 데이터 누출도 포함한다. 생성 출력은 사전에 기준을 고정한 루브릭 기반 인간 평가가 필요하다.

평가 지표와 각 지표가 숨길 수 있는 실패
지표답하는 질문숨겨지는 실패
정확도전체 사례 중 올바르게 레이블된 비율희귀 클래스에서의 실패
정밀도표시된 사례 중 실제로 맞은 비율놓친 참 양성
재현율실제 사례 중 발견된 비율오경보
F1 점수정밀도와 재현율의 균형참 음성, 그리고 각 오류의 비용
보정예측 확률이 결과와 일치하는가자신 있지만 틀린 답변

08책임 있는 AI와 전문가적 판단

AI 배포는 결과를 수반하는 전문적 행위다.

  • 책임은 모델이 제안했더라도 엔지니어에게 남는다.
  • 훈련 데이터의 편향은 결정의 편향이 된다.
  • 개인 데이터에는 적법한 근거가 필요하다.
  • 생성 콘텐츠는 권리를 침해하거나 증거로 오인될 수 있다.

통제 수단은 안전 공학에서 익숙하다. 데이터와 모델을 문서화하고, 실제 사용할 모집단에서 테스트하며, 고위험 출력에는 인간 결정 지점을 두고, 배포 후 모니터링하며, 시스템을 설명하고 철회할 수 있어야 한다.

결정의 기대 비용
\[E[\text{cost}] = p_{fp} C_{fp} + p_{fn} C_{fn}\]
결정 임계값은 두 오류의 상대적 비용을 반영해야 한다

09프롬프트 엔지니어링

언어 모델의 출력 품질은 프롬프트에 의해 결정된다. 프롬프트는 생성 전에 주어지는 지시, 맥락, 예제다.

  • 효과적인 프롬프트는 작업과 대상 독자에 대해 구체적이다.
  • 모호한 힌트 대신 데이터와 예제를 제공하라.
  • 원하는 출력 형식을 명시하라.
  • 하지 말아야 할 것이 아니라 해야 할 것을 설명하라.
  • 모델에 역할(검토자, 튜터, 현장 엔지니어)을 부여하면 사용할 어휘가 정해진다.

사고 연쇄(chain-of-thought) 프롬프팅은 답하기 전에 중간 단계를 거치도록 요청하며, 산술과 다단계 추론을 측정 가능하게 개선한다. 온도(temperature)는 샘플링 무작위성을 제어한다. 낮은 값은 가장 확률 높은 토큰을 반복하여 결정적이고 안전한 출력을 주고, 높은 값은 유창함을 다양성과 환각으로 맞바꾼다.

온도 스케일 소프트맥스
\[p(w_i) = \frac{e^{z_i/T}}{\sum_j e^{z_j/T}}\]
T → 0이면 가장 가능성 높은 토큰을 선택하고, T가 클수록 분포가 평탄해진다

10생성 미디어: 이미지, 오디오, 비디오

확산 모델은 점진적으로 노이즈를 더하는 과정을 역으로 학습하여 이미지를 생성한다. 샘플링은 순수 노이즈에서 시작하여 텍스트 설명이나 다른 조건에 이끌려 단계별로 노이즈를 제거한다. 오디오 모델은 음성과 음악을 위해 파형이나 스펙트로그램에 같은 아이디어를 적용하며, 비디오 생성은 추가로 연속 프레임의 일관성을 유지해야 한다.

생성 미디어는 기본적으로 증거가 없는 것으로 취급하라. 합성 얼굴과 음성은 생산하기 쉽고 사람이 탐지하기 어렵다. 검증은 출처(워터마크, 서명된 메타데이터, 탐지 도구)와 라벨링 같은 프로세스 통제에 의존하며, 시청자에게 가짜를 찾아내라고 요구하는 것에 의존하지 않는다.

확산 훈련 목표
\[L = \mathbb{E}\left\lVert \varepsilon - \varepsilon_\theta(x_t, t) \right\rVert^2\]
네트워크는 손상된 샘플에 더해진 노이즈 ε를 예측하도록 학습한다

11코드 생성과 그 한계

대규모 언어 모델은 자연어, 부분 프로그램, 실행 예제로부터 코드를 작성하며, 코딩 어시스턴트는 탭 완성과 채팅 기반 편집을 결합한다.

  • 상용구, 정규식, 테스트 스캐폴딩에 강하다.
  • 맥락이 길거나, 라이브러리가 생소하거나, 정답이 모델이 본 적 없는 사실에 의존할 때 약하다.

pass@k는 표준 측정치다. k번의 생성 시도 중 적어도 하나가 제공된 모든 테스트를 통과할 확률이다. 따라서 평가는 테스트 스위트만큼만 좋다. 컴파일되는 코드도 여전히 틀릴 수 있다. 생성된 코드는 인간 코드와 똑같이 검토하라. 테스트를 실행하고, 환각된 라이브러리 함수를 확인하며, 안전에 관련된 모든 것에는 인간 책임자를 두라.

Pass@k
\[\text{pass@}k = 1 - (1 - p)^k\]
p는 한 샘플이 통과할 확률이며, 시도가 많을수록 확률은 오르지만 연산 비용이 든다
환각된 API 생성된 코드는 존재하지 않는 함수나 라이브러리를 호출할 수 있다. 신뢰하기 전에 테스트 하네스에서 실행하고, 자격 증명이나 개인 데이터를 공개 모델에 절대 붙여넣지 마라.

Key terms

허용 가능 휴리스틱
남은 비용의 추정치가 실제 비용을 결코 초과하지 않게 하는 것으로, A* 탐색의 최적성을 유지한다.
과적합
훈련 데이터에 너무 밀접하게 맞추어 새롭고 보지 못한 데이터에서의 성능이 떨어지는 것.
정밀도
모델이 표시한 사례 중 실제로 양성인 비율.
환각
유창하고 그럴듯하지만 근거가 없거나 거짓인 생성 콘텐츠.
확산 모델
점진적 노이즈 추가 과정을 역으로 학습하여 샘플을 생성하는 생성 모델.
일반화
모델이 훈련받지 않은 데이터에서의 성능으로, 홀드아웃 테스트 세트로 추정한다.
프롬프트 엔지니어링
언어 모델이 원하는 출력을 생성하도록 지시, 맥락, 예제를 설계하는 것.
온도
토큰 확률을 스케일링하는 샘플링 매개변수로, 낮은 값은 결정적이고 높은 값은 더 다양하다.
Worked example

결함 탐지기의 혼동 행렬 읽기

비전 모델을 500장의 검사 이미지로 테스트한다. 결함 있는 패널 92개를 올바르게 표시하고, 정상 패널 362개를 올바르게 통과시킨다. 정상 패널 18개를 잘못 표시하고, 결함 패널 28개를 놓친다. 정확도, 정밀도, 재현율을 계산하고, 정확도만으로는 왜 오해를 부르는지 설명하라.

  1. 혼동 행렬: TP = 92, FP = 18, FN = 28, TN = 362, 총 500장.
  2. 정확도 = (TP + TN) / 전체 = (92 + 362) / 500 = 454 / 500 = 0.908, 즉 90.8퍼센트.
  3. 정밀도 = TP / (TP + FP) = 92 / 110 = 0.836, 즉 83.6퍼센트.
  4. 재현율 = TP / (TP + FN) = 92 / 120 = 0.767, 즉 76.7퍼센트.
  5. F1 = 2PR / (P + R) = 2 × 0.836 × 0.767 / (1.603) = 0.80.
  6. 기준선 확인: 항상 정상이라고 말하는 모델은 아무것도 탐지하지 못하면서 380 / 500 = 76퍼센트 정확도를 기록하므로, 정확도만으로는 불균형 데이터 세트에서 모델을 실제보다 좋게 보이게 한다.
Answer정확도는 90.8퍼센트, 정밀도는 83.6퍼센트, 재현율은 76.7퍼센트이며 F1은 약 0.80이다. 결함 패널 네 개 중 하나꼴로 놓치므로, 안전 관련 검사 작업에서는 재현율을 높이도록 임계값을 옮기고 오경보 비용을 놓친 결함 비용과 견주어 저울질해야 한다.
