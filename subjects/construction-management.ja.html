01システムとしてのプロジェクト

建設プロジェクトは、時間・コスト・品質の制約の中で定義されたスコープを遂行するために編成される一時的な組織である。スコープ、スケジュール、コスト、品質、リスク、資源、ステークホルダーは相互依存しており、一つが変われば他も動き、変更を吸収するコストはプロジェクトが進むにつれて急激に上昇する。

統合とは、こうしたトレードオフを可視化し、意思決定し続けることであり、各専門分野が単独で最適化するに任せることではない。クライアントの要求事項が基準点となる：何が必要か、何が除外されるか、成功をどう測定するかを明確に述べることで、その後の紛争のほとんどを防ぐことができる。

02ワーク・ブレークダウンと工程計画

工程計画はワーク・ブレークダウン構造から始まる：スコープをパッケージに分割し、各パッケージをアクティビティとし、アクティビティを論理で結び、期間と資源を与える。

  • ネットワークは論理を示し、ガントチャートは同じ工程をカレンダー上に示してよりよく伝達する。
  • 工程は予測であり記録ではないため、作業と情報の変化に応じて更新される。
  • 資源平準化は、人員を配置できないピークを平らにする。
  • クラッシングは資源を追加してクリティカルパスを短縮するが、通常は追加コストを伴う。
  • いずれもリスクプロファイルを変えるため、黙って行うべきではない。

03クリティカルパスとフロート

クリティカルパスはネットワークを通る最長の経路であり、したがってプロジェクト期間を定める。フォワードパスは最早開始と最早終了を与え、バックワードパスは最遅開始と最遅終了を与える。

  • トータルフロートは、完成を遅らせずにアクティビティが遅れられる時間であり、フロートがゼロのアクティビティがクリティカルである。
  • フロートはプロジェクトに属し、一つの職種のものではない。早期に使うと、後の遅延を吸収できたバッファーが失われるため、フロートは必ずしも余裕時間ではない。
  • フリーフロートは、次のアクティビティの最早開始に影響せずに使える、より小さい時間である。
最早終了
\[\mathrm{EF} = \mathrm{ES} + \text{duration}\]
ESはフォワードパスから得られる最早開始
トータルフロート
\[\mathrm{TF} = \mathrm{LS} - \mathrm{ES} = \mathrm{LF} - \mathrm{EF}\]
最遅開始と最遅終了はバックワードパスから得られる

04クラッシングとコスト・時間のトレードオフ

クラッシングは、より多くの作業班、より多くの機械、より長いシフト、またはより速い工法によって、資金を費やしてアクティビティを短縮する。アクティビティがクリティカルパス上にある場合にのみ効果があり、フロートのあるアクティビティに費やしても何も得られない。

コストスロープはこのトレードオフに価格を付ける — 節約される1日あたりの追加コスト — であり、最も安いスロープからクラッシングする。アクティビティを圧縮するにつれて容易な節約が尽きるため、スロープは上昇する。限界を超えるとアクティビティはまったく短縮できず、急ぎの下では品質と安全が悪化する。したがってクラッシングは単一の決定ではなくスロープの順位リストであり、各ステップの後にネットワークを再計算しなければならない。

コストスロープ
\[\mathrm{CS} = \frac{C_c - C_n}{t_n - t_c}\]
クラッシュコストと時間を通常コストと時間に対して；最小のスロープからクラッシングする

05調達と契約

調達は、誰が設計し、誰が施工し、誰がどのリスクを負うかを決める。

  • 伝統的設計・入札・施工：クライアントが設計を保有する。
  • 設計施工一括：一つの組織が設計と施工の両方を保有する。
  • マネジメント・コントラクティング：施工者を早期に参画させ、設計の進展に応じてパッケージを発注する。
  • 各方式は、コストの確実性を速度、柔軟性、クライアントの変更へのエクスポージャーとトレードオフする。

契約は方式に適合しなければならない：一括請負、精算請負、またはコストプラスで、変更、遅延、支払いに関する明確な条項を備える。ほとんどの紛争は、方式、契約、期待の不一致に起因する。

調達方式とリスクの所在
方式設計責任発注時のコスト確実性適する場合
伝統的クライアントの設計者高い（スコープが固定されている場合）施工前に設計が完了している場合
設計施工一括請負者高い（単一責任）一者が設計と施工を保有する場合
マネジメント・コントラクティングクライアントの設計者、パッケージを早期発注低い速い工程、複雑なプロジェクト
コストプラスクライアントの設計者低いスコープを事前に定義できない場合

06契約管理：変更とクレーム

契約は発注後に変更される。変更とは、作業に対する指示された変更である：追加、削除、異なる材料、または変更された順序。仕組みは変更そのものと同じくらい重要である — 誰が指示できるか、どのように評価されるか、当事者が合意しない場合にどうなるか。

クレームは、一方の当事者が他方の行為またはリスク事象によって時間や費用を被ったと考える場合に生じる。権利のテストは規律正しい：契約上の根拠があったか、通知は期限内に出されたか、事象をクリティカルパスに結び付けられるか。時間延長は違約金を免除するが、自動的に金銭を伴うわけではなく、それは誰がリスクを負っていたかによる。

クレーム権利のテスト
ground → notice → records → causation → quantum
各リンクが成立しなければならない；期限を過ぎた通知は、それ以外は有効なクレームを無効にする
通知なきは権利なし ほとんどの契約形式は事象から数日以内の通知を要求する；数か月後に主張された有効な権利は通常拒否されるため、日付、原因、影響を直ちに記録すること。

07コスト管理とアーンドバリュー

コスト管理は、支出されたものと稼得されたものを比較する。アーンドバリューは、計画価値（PV）＝予定作業の予算、アーンドバリュー（EV）＝完了作業の予算、実コスト（AC）を用いる。

  • コスト性能指数 CPI = EV/AC とスケジュール性能指数 SPI = EV/PV は、プロジェクトが各次元で先行しているか遅れているかを示す。
  • CPIが1未満は作業単位あたりのコスト超過を意味し、完成時総コスト EAC = BAC/CPI は傾向が続く場合の最終コストを予測する。
  • キャッシュフローは別である：支払いが支出に遅れれば、収益性のあるプロジェクトでも失敗し得る。
コスト性能指数
\[\mathrm{CPI} = \frac{\mathrm{EV}}{\mathrm{AC}}\]
1未満は作業が予算より高くついていることを意味する
スケジュール性能指数
\[\mathrm{SPI} = \frac{\mathrm{EV}}{\mathrm{PV}}\]
1未満は作業がスケジュールより遅れていることを意味する
完成時総コスト
\[\mathrm{EAC} = \frac{\mathrm{BAC}}{\mathrm{CPI}}\]
現在のコスト傾向が続くと仮定する

08Sカーブと進捗測定

進捗はめったに線形ではない：着手はゆっくり始まり、生産はピークに達し、その後仕上げと試運転は徐々に減少する。したがって時間に対する累積進捗はSカーブとして描かれ、計画曲線が実績を描く基準線となる。

ある日付における計画と実績の垂直方向の差は価値の観点でスケジュールのずれを示し、水平方向の差はプロジェクトが何日遅れたかを示す。出来高率は測定された数量から得られ、支出額からではない — 支出は完了を意味しない — そして曲線は各点の背後にある評価と同じだけ正直である。

出来高率
\[\mathrm{PC} = \frac{\mathrm{EV}}{\mathrm{BAC}}\]
完成時予算に対するアーンドバリューをパーセントで表す
完成時時間予測
\[\mathrm{TEAC} = \frac{T}{\mathrm{SPI}}\]
計画期間Tをスケジュール性能指数で割る

09現場における進捗、記録、品質

現場記録はプロジェクトの記憶である：日報、日誌、写真、測定シート、納品書、往復文書。それらは支払い、進捗評価、変更クレーム、そして必要なら紛争解決を支える。当日に作られた記録は証拠であり、後から再構成されたものは主張である。

品質は検査・試験計画、ホールドポイント、署名済みチェックシートによって管理され、不適合は記録され閉じられる。引き渡し前の手直しは入居後の是正より安く、竣工時情報は設計と現実の間のループを閉じる。

10ステークホルダーとコミュニケーション

プロジェクトはコンクリートと同じくらいステークホルダーによって成功または失敗する：クライアント、利用者、近隣住民、当局、公益事業者、公衆はすべて、要求や反対に変わり得る期待を抱いている。ステークホルダー管理は、彼らが誰か、何を必要とするか、各段階で誰に情報を提供し続けるべきかを整理する。

コミュニケーションは一定のリズムで行われる：毎日の現場ブリーフィング、毎週の進捗会議、毎月の報告、許認可と支払いのための正式な提出。情報要求、図面送付、指示は記録され閉じられる。なぜなら、答えのない質問は、今日の日付が付いた将来の遅延クレームだからである。

建設記録とそれぞれが守るもの
記録捉える内容守るもの
現場日誌天候、労務、機械、来訪者、出来事遅延・妨害クレーム
情報要求回答待ちの設計上の疑問情報遅延クレーム
変更指示指示された変更とその評価変更作業の支払い
検査・試験計画チェック、基準、立会者品質・欠陥紛争
写真ある日付の物理的状態紛争における証拠

11BIMコーディネーションとデジタルデリバリー

統合されたビルディング・インフォメーション・モデルにより、設計チームは施工前に構造、設備、建築を一緒に見ることができる。クラッシュ検出は物理的衝突を見つけ、4Dシーケンシングはモデルオブジェクトを工程に結び付け、5D数量拾いはそれらを数量とコストに結び付ける。コーディネーション会議はクラッシュレポートを処理し、モデルに対して決定を記録する。

モデルはその情報と同じだけ優れている。明確な命名、共通データ環境、定義された情報要求、バージョン管理が、誤った改訂版に上書きするデジタル版を防ぐ。BIMはコーディネーションをなくすのではなく、コーディネーションを可視化する。

12健康、安全、リスク

安全は設計と作業計画によって管理される。管理の階層は、危険の除去、より安全な方法への置換、工学的手段、管理的手段を優先し、個人用保護具は最後である。方法書と作業許可証はその階層を現場実務に翻訳する。

リスク管理も同じ論理に従う：特定、可能性と結果の評価、処理、監視。ヒヤリハット報告は、誰かが負傷する前に失敗を明らかにするため価値がある。安全な現場は通常よく計画された現場であり、急ぎと整理整頓の不足は工程圧力の症状である。

Key terms

ワーク・ブレークダウン構造
プロジェクトのスコープを、計画・見積・管理可能なパッケージに階層的に分割したもの。
クリティカルパス
アクティビティ・ネットワークを通る最長の経路；その長さがプロジェクト期間を定め、その上のアクティビティはトータルフロートがゼロである。
トータルフロート
プロジェクトの完成日を遅らせずにアクティビティを遅延できる時間。
アーンドバリュー
実際に完了した作業の予算価値であり、進捗とコストを計画と比較するために用いる。
コスト性能指数
アーンドバリューを実コストで割ったもの；1未満の値はコスト超過を示す。
クラッシュ検出
建物要素や設備間の物理的衝突について統合モデルを自動チェックすること。
変更
契約締結後の工事に対する指示された変更であり、契約の仕組みに従って評価されなければならない。
時間延長
免責される遅延に対して与えられる追加時間であり、違約金を免除するが自動的に金銭を与えるものではない。
Worked example

小規模内装工事のクリティカルパスとフロート

内装工事には5つのアクティビティがある：A 現場設営（3日、先行なし）；B 間仕切り（4日、Aの後）；C 一次設備（2日、Aの後）；D 仕上げ（5日、BとCの後）；E 引き渡しと手直し（1日、Dの後）。プロジェクト期間、クリティカルパス、アクティビティCのトータルフロートを求めよ。

  1. フォワードパス：Aは0〜3；Bは3〜7；Cは3〜5；DはBとCの両方が完了したときにのみ開始できるため、7日目に開始し12日目に終了する；Eは12〜13。
  2. バックワードパス：Eの最遅開始は12；Dの最遅開始は7；BとCはともに7日目までに終了しなければならず、Bの最遅開始は3、Cの最遅開始は5；Aの最遅開始は0。
  3. TF = LS − ES よりトータルフロート：AとBはゼロ、Cは5 − 3 = 2日、DとEはゼロ。
  4. クリティカルパスはフロートゼロのアクティビティの連鎖：A → B → D → E、期間は3 + 4 + 5 + 1 = 13日。
  5. アクティビティCは引き渡しを遅らせずに最大2日遅れられるが、Bがクリティカルパス上にある間のみである。
Answerプロジェクト期間は13日、クリティカルパスはA → B → D → E、アクティビティCのトータルフロートは2日である。

Exam method

  • ガントチャートより先にネットワークを描く；フロートは論理の結果であり、棒グラフの結果ではない。
  • 指数や差異が有利か不利かを述べ、使用した数値を示す。
  • 調達の質問では、方式の名前だけでなく、リスク配分とコストの確実性で答える。
  • アーンドバリューの定義を正確に保つ：EVは完了作業の予算であり、それに費やした金額ではない。
  • クリティカルパス上の最も安いスロープからクラッシングし、各ステップの後にネットワークを再計算する — クラッシングはクリティカルパスを移動させ得る。
