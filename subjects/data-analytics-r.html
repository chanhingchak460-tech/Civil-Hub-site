R turns a spreadsheet of measurements into a defensible argument: tidy the data, describe it, plot it, fit it and forecast it. Most of the skill lies in the order of those steps and in scripts that someone else can re-run.

01Start with the data frame

A data frame is the unit of work: each row is one observation and each column is one variable. R keeps columns as vectors, so measurements stay numeric while categories should be factors.

read.csv() only reads the file; then check the shape with str() and head(). Tidy data means one row per case, one column per variable and one value per cell. Most later trouble — numbers imported as text, dates stored as characters — is visible here, and fixing it early is cheaper than patching a model.

Describe before modelling. summary() gives range, quartiles and missing counts; mean(), median(), sd() and IQR() give the numbers you will quote. A mean far from the median hints at skew or a stray observation.

Read, inspect, describe 
pm <- read.csv('data/pm.csv')
str(pm); dim(pm); head(pm)
summary(pm$value); sd(pm$value, na.rm = TRUE)
relative paths keep the script portable

02Wrangle with verbs, not loops

Wrangling is a sequence of small verbs, each doing one thing:
- filter() keeps rows
- select() keeps columns
- mutate() adds a column
- arrange() sorts
- group_by() with summarise() gives one summary row per group

The pipe |&gt; passes each result into the next step, so the code reads in reasoning order. If a step is hard to name, it is doing two jobs and should be split. group_by() with summarise() also replaces most hand-written loops over categories.

A small grouped pipeline 
daily <- pm |>
  filter(!is.na(value)) |>
  mutate(month = format(date, '%m')) |>
  group_by(month) |>
  summarise(mean_pm = mean(value), n = n())
one row per month, with the count beside the mean

03Hunt missing values and outliers

Missing values are not neutral: they shrink the sample and bias a mean if they cluster in one period or one site. Count them with mean(is.na(x)), then decide to drop, impute or model them — and write the decision down.

Outliers need a decision too. A reading twenty times the others may be a real event or a typing error, and the two deserve different treatment. A boxplot shows the shape; a log scale sometimes tames a long tail.

Share of missing values
mean(is.na(x))
a proportion from 0 to 1, not a count

04Plots are arguments about data

The grammar of graphics splits a plot into data, an aesthetic mapping and a geometry. In ggplot(), aes() says which variable controls x, y, colour or shape, and the geom says what is drawn. Changing the geometry changes the claim.

Colour should encode a variable, not decorate. facet_wrap() makes small multiples, often clearer than five layered lines. Label both axes and give the title the takeaway; ggsave() keeps the figure reproducible.

Points with a mapped colour
ggplot(pm, aes(x = date, y = value, colour = site)) + geom_point() + labs(x = 'Date', y = 'PM2.5 (µg/m³)')
colour encodes the site

05Regression: a fitted line, not a law

lm(y ~ x, data = pm) fits the least-squares line. The slope is the expected change in y per one-unit change in x, so its units matter and its sign must make physical sense. R² is the share of variance in y explained by the model, not the probability that it is correct.

Always inspect residuals: a curve means the relationship is not linear, a fan shape means the variance changes, and a few extreme points may dominate the fit. Correlation is not causation, and extrapolation beyond the observed range is not evidence.

Simple linear model
\[y = \beta_0 + \beta_1 x + \varepsilon\]
ε collects what the line does not explain
Coefficient of determination
\[R^2 = 1 - \frac{\mathrm{SSE}}{\mathrm{SST}}\]
the proportion of variation explained

06Time series, seasonality and ARIMA

A time series is ordered, so neighbouring values are related and ordinary regression assumptions fail. Convert with ts(x, frequency = 12) for monthly data, then plot it: trend, repeating seasonality and noise should be visible. decompose() splits the series into those parts.

A series is stationary when its mean, variance and autocorrelation do not drift with time. Differencing removes a trend; the autocorrelation and partial autocorrelation plots then suggest the orders of an ARIMA(p, d, q): p autoregressive terms, d differences, q moving-average terms. auto.arima() searches, and forecast() reports values with widening prediction intervals — a forecast without that interval is half an answer.

Additive decomposition
\[y_t = T_t + S_t + E_t\]
trend, seasonal and remainder
First difference
\[\Delta y_t = y_t - y_{t-1}\]
removes a linear trend
ARIMA model
\[\varphi(B)(1 - B)^d y_t = \theta(B)\,\varepsilon_t\]
B is the backshift operator

07Scripts that someone else can run

A result is only as good as the script behind it. Set the seed before any simulation with set.seed(), read data through relative paths, and never edit the raw file by hand — keep cleaning as code. Save output in a different folder from the input.

Comment the why, split long work into functions, and record package versions. A short readme saying how to run the script is part of the analysis: a reproducible script makes a number checkable.

Fix the random seed 
set.seed(1234)
same seed, same simulated sample

08Hypothesis tests in R

R packages the classic tests as one-liners, and the discipline is the same as on paper: state the null hypothesis before running anything. t.test(x, mu = 40) tests one sample against a value, t.test(x, y) compares two groups, and paired = TRUE switches to a test of the differences. chisq.test(table) handles counts and aov() fits an analysis of variance.

Read the output as a whole: the p-value answers significance, the confidence interval shows the size of the effect, and the degrees of freedom say how much evidence sits behind them. A tiny p-value with a minuscule interval can be statistically significant and practically irrelevant.

One-sample and two-sample t tests
t.test(x, mu = 40) t.test(x, y, alternative = 'two.sided', paired = FALSE)
state alternative and paired explicitly; defaults can silently change the test

09Joining and reshaping tables

Real analyses rarely arrive in one tidy file. Joins combine tables by shared keys: left_join(a, b, by = 'site') keeps every row of a and brings matching columns from b, while inner_join() keeps only rows present in both and anti_join() finds rows with no match — the tool for spotting missing sites.

Reshaping moves the same values between wide and long layouts. pivot_longer() gathers many columns into key-value rows, and pivot_wider() spreads them back. Long form is what ggplot() and grouped summaries want. Check the row count before and after every join, because duplicated keys silently multiply rows.

Join and pivot 
readings <- left_join(sites, readings, by = 'site')
long <- readings |>
  pivot_longer(cols = starts_with('month'), names_to = 'month', values_to = 'value')
one row per site-month after pivoting

10Generalised linear models with glm()

A binary outcome — passed or failed, defective or sound — cannot be fitted well by ordinary least squares, because a straight line predicts probabilities outside 0 and 1. glm(y ~ x, family = binomial) fits logistic regression, which passes a linear score through the sigmoid so predictions stay between 0 and 1.

predict(model, newdata, type = 'response') returns probabilities; without type = 'response' it returns log-odds, which are easy to misread. Convert a probability to a class with your chosen threshold, and report precision and recall for the minority class rather than overall accuracy.

Logistic link
\[p = \frac{1}{1 + e^{-(\beta_0 + \beta_1 x)}}\]
the sigmoid maps the linear score into (0, 1)
Fit and predict 
fit <- glm(pass ~ strength, data = cubes, family = binomial)
pred <- predict(fit, newdata = new_cubes, type = 'response')
type = 'response' gives probabilities, not log-odds
Ask for probabilities explicitly predict() on a binomial glm returns log-odds unless you set type = 'response'; a forgotten argument turns 0.80 into −1.39.

Key terms

Data frame
A table in which each column is a variable and each row an observation, the basic working object in R.
Tidy data
A layout with one row per case, one column per variable and one value per cell.
Pipe
The operator that passes the result of one step as the first argument of the next, so code reads in execution order.
Residual
The difference between an observed value and the value predicted by the fitted model.
Stationarity
A property of a time series whose mean, variance and autocorrelation do not change with time.
Coefficient of determination
R², the proportion of the total variation in the response explained by the fitted model.
Generalised linear model
A model fitted with glm() that links a linear score to a non-normal outcome, such as logistic regression for binary responses.
Left join
A table join that keeps every row of the first table and adds matching columns from the second.
Worked example

Reading and interpreting a summary of daily readings

A file holds ten daily PM2.5 readings (µg/m³) from one monitor: 18.0, 21.5, 19.2, 24.8, 60.1, 22.3, 20.6, 23.4, 19.9, 21.0. Read the values in R and compute the mean, median, standard deviation and interquartile range. Say what the numbers imply about a typical day at this monitor.

  1. Read the file into a data frame and pull out the column: d <- read.csv('pm.csv'); x <- d$value. Confirm n = 10 with length(x).
  2. Mean: sum(x)/length(x) = 250.8/10 = 25.1 µg/m³.
  3. Median: the two middle values are 21.0 and 21.5, so the median is 21.25 ≈ 21.3 µg/m³.
  4. Standard deviation: the sum of squared deviations is about 1398, so the sample variance is 1398/9 ≈ 155.3 and sd ≈ 12.5 µg/m³.
  5. Quartiles: Q1 = 20.1 and Q3 = 23.1, so IQR = 3.0 µg/m³.
  6. Compare the mean, 25.1, with the median, 21.3. Removing the single reading of 60.1 leaves a mean of 21.2, almost exactly the median.
AnswerMean 25.1 µg/m³, median 21.3 µg/m³, sd 12.5 µg/m³, IQR 3.0 µg/m³. Nine of the ten days sit close to 21 µg/m³, so the mean is pulled up by one spike and the median describes a typical day better; the sd is inflated by the same point. Always report a spread alongside a centre.

Exam method

  • Say what each summary statistic assumes: the mean is sensitive to extremes, the median is not.
  • When asked to interpret a regression slope, give its units and check its sign makes physical sense.
  • For time-series questions, name the trend, the seasonal period and whether the series needs differencing before quoting an ARIMA order.
  • Mention reproducibility (seed, relative path, saved script) in any write-up; it is a mark-earning sentence, not padding.
  • Set alternative = and paired = explicitly in t.test() — the defaults quietly change what the test means.

Q01Which function fits a linear regression model in base R?

Whylm() fits a linear model by least squares; glm() fits a generalised linear model and the others do something else entirely.

Q02In a pipeline such as pm |> filter(value > 0), the filter receives:

WhyThe pipe places the left-hand object into the first argument of the function on the right, which is the data frame here.

Q03A time series has a clear upward trend. Which step most directly makes it closer to stationary?

WhyDifferencing removes the trend so the mean of the differenced series no longer drifts, which is the d term in ARIMA.

Q04group_by(month) followed by summarise(mean_pm = mean(value)) returns:

WhyEach group is collapsed into one summary row, so the result has as many rows as there are distinct months.

Q05Which single line tests whether the mean of x equals 40?

Whyt.test(x, mu = 40) runs a one-sample t test against the hypothesised mean 40; the other forms misuse the arguments.

Q06A wide table has one column per month. The function that turns it into one row per month, with columns for the month name and the reading, is:

Whypivot_longer() gathers several columns into key-value rows, producing the long, tidy layout.
