Choosing a data structure is a decision about cost. This page covers arrays, lists, stacks, queues, hash tables, trees and graphs, then sorting, searching and the Big-O language used to compare them.

01The structure is part of the algorithm

An abstract data type is a contract: the operations and their meaning, with no promise about implementation. A data structure is one way to keep that contract, and every implementation trades something — time for memory, or generality for speed.

  • Finding whether a value exists: linear scan in an unsorted array, logarithmic search in a sorted one, average constant-time lookup in a hash table.
  • Name the operations the program performs most often before writing code.

02Arrays and linked lists

An array stores elements in contiguous memory, so indexing is constant-time arithmetic, but inserting in the middle shifts everything after it. A linked list stores nodes that point to each other: inserting at a known node is constant-time, yet reaching position k means walking k nodes, and each step may miss the cache.

  • Use arrays for indexed reading and iteration; lists for splicing and reordering without random access.
  • A dynamic array amortises growth by doubling capacity, which makes appending O(1) on average.

03Stacks and queues

A stack is last-in, first-out: push and pop at one end. It models nested structure — function calls, bracket matching, depth-first traversal, undo history. A queue is first-in, first-out: enqueue at the back, dequeue at the front. It models fair service and breadth-first traversal, such as exploring a road network by distance from the start.

  • A plain array queue wastes space as the front advances; a circular buffer reuses it.
  • A deque allows both ends in constant time.

04Hash tables

A hash table maps a key to a bucket by computing h(key), aiming for constant-time average lookup, insertion and deletion. Collisions are unavoidable; separate chaining stores a list per bucket, while open addressing probes other slots in a fixed sequence.

  • Performance depends on the load factor, the ratio of stored keys to buckets.
  • Small tables and poor hash functions turn expected O(1) into O(n).
  • Never rely on iteration order, and rehash by doubling when the load factor passes a threshold.
Load factor
\[\alpha = \frac{n}{m}\]
n keys in m buckets; keep α below about 0.75

05Trees and heaps

A binary search tree keeps smaller keys left and larger keys right, so search costs the height of the tree: O(log n) when balanced, O(n) when degenerate. Balanced trees rebalance on insertion and guarantee logarithmic height.

  • A heap keeps only a partial order — every parent smaller than its children for a min-heap — which is enough for a priority queue.
  • Push and pop cost O(log n), reading the extreme costs O(1), and the structure lives in a flat array.

06Balance and rotations

A search tree is only logarithmic while it stays balanced. An AVL tree keeps, at every node, the heights of the two subtrees within one of each other; when an insertion breaks that rule, a rotation restores it.

  • A single rotation fixes an outside-heavy shape, while a double rotation fixes the zig-zag inside shape.
  • Rotations are local pointer surgery: constant time, but they must update parent links and the stored heights.
  • Red–black trees relax the rule to a colouring scheme that needs at most a constant number of rotations per insertion.
  • In exams, name the invariant first, apply the rotation second, and update the metadata third.
AVL balance factor
\[\mathrm{BF} = h_L - h_R \in \{-1, 0, +1\}\]
an insertion or deletion may break it; one or two rotations restore it
Heap array indices
children of i: 2i + 1 and 2i + 2; parent: (i − 1) // 2
zero-based array layout of a binary heap

07Graphs and how to walk them

A graph is vertices plus edges, with weights for distance or travel time.

  • An adjacency list stores neighbours per vertex and suits sparse networks.
  • An adjacency matrix uses n² memory and answers "is there an edge?" in constant time, which suits dense ones.
  • Breadth-first search explores by layers and finds shortest paths when every edge has the same weight.
  • Depth-first search follows one branch as far as possible and exposes cycles, components and topological order.
  • Weighted shortest paths need Dijkstra's algorithm, which expands the cheapest unvisited vertex using a priority queue.

08Greedy algorithms and shortest paths

A greedy algorithm commits to the locally best choice and never revisits it. That works when a problem has optimal substructure plus a safe greedy choice: activity selection keeps the earliest-finishing compatible activity, and Huffman coding repeatedly merges the two rarest symbols.

  • Dijkstra's algorithm is greedy relaxation: repeatedly settle the unsettled vertex with the smallest known distance, then relax its edges.
  • It requires non-negative weights; with negative edges, use Bellman–Ford, which relaxes every edge n−1 times and detects negative cycles on one extra pass.
  • When asked to justify a greedy algorithm, state the choice and why it is safe.
Edge relaxation
\[d[v] = \min(d[v],\; d[u] + w(u,v))\]
u is settled, u→v is an edge of weight w

09Sorting, searching and Big-O

Big-O describes how cost grows with input size, ignoring constants and lower-order terms. It is a language of growth rates, not a stopwatch: an O(n²) sort can beat an O(n log n) sort on small arrays because its overhead is smaller.

  • Comparison sorting cannot beat Ω(n log n).
  • Merge sort guarantees O(n log n) and is stable but needs extra memory.
  • Quicksort is fast in practice but degrades to O(n²) on adversarial pivots.
  • Insertion sort is excellent on nearly sorted data.
  • Binary search halves the range each step, so it needs only logarithmic comparisons.
Binary search comparisons
\[C \le \lceil \log_2 n \rceil + 1\]
for a sorted array of n elements

10Growth rates and the Master theorem

Recurrences describe divide-and-conquer costs, and the Master theorem solves the common shape by comparing the split-and-combine work with the work done in the leaves.

  • When the combining term dominates, the total is the combining cost.
  • When the leaves dominate, it is the leaf cost.
  • When the two balance, the answer gains a log factor.
  • The trap is notation, not algebra: O is an upper bound, Ω a lower bound and Θ both, and they describe growth classes, not specific run times.
  • Practise ordering classes such as log n, √n, n, n log n, n² and 2ⁿ before the exam, and check every answer against a small case.
Master theorem shape
\[T(n) = aT(n/b) + f(n)\]
compare f(n) with n^(log_b a); whichever grows faster decides the total
Do not force the Master theorem It only applies to recurrences of the shape T(n) = aT(n/b) + f(n) with equal-sized subproblems. For irregular splits, draw the recursion tree and sum the levels instead.

11Recursion and the time-memory trade-off

A recursive function solves a problem by calling itself on a smaller input; every call adds a frame to the call stack, so depth is memory. The recurrence T(n) = 2T(n/2) + O(n) resolves to O(n log n), while a branching recurrence with repeated subproblems can explode exponentially.

  • Dynamic programming removes that blow-up by storing each subproblem once.
  • Memoisation keeps the top-down recursion and caches results; the bottom-up form fills a table in dependency order.
  • Both spend memory to buy time, so inspect a recurrence for repeated work before implementing it.
Divide-and-conquer recurrence
\[T(n) = 2T(n/2) + O(n) \rightarrow O(n\log n)\]
two halves of equal size plus linear work
Dynamic programming recurrence
\[r(n) = \max_{1 \le i \le n} (p(i) + r(n-i))\]
each subproblem solved once

12Topological order and cycle detection

A directed acyclic graph (DAG) models tasks with prerequisites, and a topological order lists the vertices so that every edge points forward.

  • Kahn's algorithm repeatedly removes a vertex whose in-degree is zero; if the process stops with vertices remaining, the graph contains a cycle.
  • Depth-first search gives the same order via reversed finishing times.
  • Cycle detection and topological sorting appear whenever a programme, a dependency set or an assembly sequence must be shown to be feasible.
  • For scheduling questions, draw the precedence graph first, compute the in-degrees, and simulate the queue — the order you obtain is one valid answer, not necessarily the only one.
In-degree update
for each edge u→v: indegree[v] = indegree[v] − 1
after removing u; any vertex reaching zero joins the queue

Key terms

Abstract data type
A specification of operations and their behaviour, independent of any implementation.
Load factor
The number of stored keys divided by the number of buckets; it controls hash-table performance.
Binary search tree
A tree with smaller keys on the left and larger keys on the right, searched in height time.
Heap
A tree with a partial order between parent and child, used to implement a priority queue.
Big-O
An asymptotic upper bound on how an algorithm's cost grows with input size, up to constant factors.
Dynamic programming
Solving a problem by storing and reusing the answers to its overlapping subproblems.
AVL tree
A self-balancing binary search tree whose nodes keep left and right subtree heights within one of each other.
Topological order
A linear ordering of a DAG's vertices in which every edge points from an earlier to a later vertex.
Worked example

Inserting into a hash table with chaining

A hash table has m = 7 buckets, uses h(k) = k mod 7 with separate chaining, and inserts the keys 25, 38, 41, 7, 52, 61, 33 and 14 in that order, each prepended to its chain. Show the final table, its load factor, and the number of comparisons needed to find 38 and 61.

  1. Bucket index for each key: 25 → 4, 38 → 3, 41 → 6, 7 → 0, 52 → 3, 61 → 5, 33 → 5, 14 → 0.
  2. Inserting in order and prepending: bucket 4 holds 25; bucket 3 grows to 52 → 38; bucket 6 holds 41.
  3. Bucket 5 grows to 33 → 61, because 61 was inserted before 33 and prepending puts the new key first. Bucket 0 grows to 14 → 7 for the same reason.
  4. Final chains: bucket 0: 14 → 7; bucket 3: 52 → 38; bucket 4: 25; bucket 5: 33 → 61; bucket 6: 41; buckets 1 and 2 are empty.
  5. Load factor α = 8/7 ≈ 1.14, so the average chain is longer than one node and the longest chain has two nodes.
  6. Find 38: probe bucket 3, compare 52 (miss), then 38 (hit), so two comparisons. Find 61: probe bucket 5, compare 33, then 61, also two comparisons.
AnswerChains are 14 → 7 (bucket 0), 52 → 38 (3), 25 (4), 33 → 61 (5) and 41 (6); buckets 1 and 2 are empty. The load factor is 8/7 ≈ 1.14, and both searches take two comparisons. A factor above 1 justifies growing the table and rehashing, which restores the expected O(1) behaviour.

Exam method

  • Give the worst case and the average case separately; hash tables are only O(1) on average.
  • State a structure's invariant before using it — heap order, search-tree order, sorted array — because every operation depends on it.
  • For recursion, write the recurrence first, then solve or quote the Master theorem; do not guess the growth rate from the code.
  • For Dijkstra, draw the distance table and tick vertices in the order they are settled; never relax from a vertex before it is settled.

Q01A hash table with chaining contains n keys in m buckets. Its worst-case lookup cost is:

WhyThe average case is O(1) with a good hash function and low load factor, but the worst case degenerates to scanning one chain of n keys.

Q02Which structure most naturally implements breadth-first search of a graph?

WhyBFS visits vertices in the order they are discovered, so a first-in, first-out queue keeps the frontier in the right order.

Q03Memoisation speeds up a recursive algorithm mainly because it:

WhyRepeated subproblems are solved once and cached, which can turn exponential work into polynomial work at the cost of memory.

Q04Binary search can be applied to an array only when:

WhyBinary search discards half the range based on an ordering comparison, so the data must be sorted; duplicates are fine and the length need not be a power of two.

Q05Dijkstra's algorithm is valid only when:

WhyDijkstra relies on settled distances never improving later, which negative edges can break; Bellman–Ford handles negative weights instead.

Q06Kahn's algorithm stops before every vertex has been output. This proves that:

WhyKahn's algorithm removes in-degree-zero vertices; if some remain, they wait on each other in a cycle, so no topological order exists.
