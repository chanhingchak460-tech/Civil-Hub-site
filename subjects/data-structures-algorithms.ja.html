データ構造の選択はコストに関する意思決定である。このページでは配列、リスト、スタック、キュー、ハッシュテーブル、木、グラフを扱い、続いてソート、探索、そしてそれらを比較するために用いるBig-Oの言語を扱う。

01構造はアルゴリズムの一部である

抽象データ型は契約である。すなわち操作とその意味を定め、実装については何も約束しない。データ構造はその契約を守る一つの方法であり、あらゆる実装は何かを犠牲にする — メモリのために時間を、速度のために汎用性を。

  • ある値が存在するかを見つける: 未ソート配列では線形走査、ソート済み配列では対数探索、ハッシュテーブルでは平均定数時間の参照。
  • コードを書く前に、プログラムが最も頻繁に行う操作を列挙せよ。

02配列と連結リスト

配列は要素を連続したメモリに格納するため、添字アクセスは定数時間の算術で済むが、途中への挿入はそれ以降のすべてをずらす。連結リストは互いを指すノードを格納する: 既知のノードへの挿入は定数時間だが、位置kに到達するにはk個のノードをたどる必要があり、各ステップでキャッシュミスが起こりうる。

  • 添字による読み取りと反復には配列を、ランダムアクセスなしの接ぎ合わせや並べ替えにはリストを使う。
  • 動的配列は容量を倍にすることで成長を償却し、末尾追加を平均O(1)にする。

03スタックとキュー

スタックは後入れ先出し（LIFO）である: 一端でpushとpopを行う。これは入れ子構造をモデル化する — 関数呼び出し、括弧の対応、深さ優先探索、undo履歴。キューは先入れ先出し（FIFO）である: 後ろでenqueueし、前でdequeueする。これは公平なサービスと幅優先探索をモデル化する。たとえば出発点からの距離によって道路網を探索する場合などである。

  • 単純な配列キューは先頭が進むにつれて空間を浪費する; リングバッファはそれを再利用する。
  • デック（両端キュー）は両端での操作を定数時間で可能にする。

04ハッシュテーブル

ハッシュテーブルはh(key)を計算してキーをバケットに写像し、平均定数時間の参照、挿入、削除を目指す。衝突は避けられない; 分離連鎖法はバケットごとにリストを格納し、開番地法は固定の順序で他のスロットを探索する。

  • 性能は負荷率、すなわち格納されたキー数とバケット数の比に依存する。
  • 小さなテーブルと貧弱なハッシュ関数は、期待されるO(1)をO(n)に変えてしまう。
  • 反復順序に決して依存せず、負荷率がしきい値を超えたら倍に拡張して再ハッシュせよ。
負荷率
\[\alpha = \frac{n}{m}\]
m個のバケットにn個のキー; αは約0.75未満に保つ

05木とヒープ

二分探索木は小さいキーを左に、大きいキーを右に保つため、探索コストは木の高さになる: 平衡ならO(log n)、退化すればO(n)。平衡木は挿入時に再平衡化し、対数の高さを保証する。

  • ヒープは部分順序のみを保つ — 最小ヒープではすべての親がその子より小さい — これが優先度付きキューには十分である。
  • pushとpopはO(log n)、極値の読み取りはO(1)で、構造は平坦な配列に格納される。

06平衡と回転

探索木が対数時間であるのは平衡を保っている間だけである。AVL木は各ノードで二つの部分木の高さの差を1以内に保つ; 挿入がその規則を破ると、回転がそれを回復する。

  • 単一回転は外側に偏った形を修正し、二重回転は内側のジグザグ形を修正する。
  • 回転は局所的なポインタ操作である: 定数時間だが、親リンクと格納された高さを更新しなければならない。
  • 赤黒木は規則を緩和し、挿入ごとに高々定数回の回転で済む彩色方式を用いる。
  • 試験では、まず不変条件を述べ、次に回転を適用し、最後にメタデータを更新せよ。
AVL平衡係数
\[\mathrm{BF} = h_L - h_R \in \{-1, 0, +1\}\]
挿入や削除で破られうる; 1回または2回の回転で回復する
ヒープの配列添字
children of i: 2i + 1 and 2i + 2; parent: (i − 1) // 2
二分ヒープの0始まり配列レイアウト

07グラフとその探索方法

グラフは頂点と辺からなり、距離や移動時間のための重みを持つ。

  • 隣接リストは頂点ごとに隣接頂点を格納し、疎なネットワークに適する。
  • 隣接行列はn²のメモリを使い、「辺は存在するか?」に定数時間で答えるため、密なグラフに適する。
  • 幅優先探索は層ごとに探索し、すべての辺の重みが等しい場合に最短経路を見つける。
  • 深さ優先探索は一つの枝を可能な限りたどり、閉路、連結成分、トポロジカル順序を明らかにする。
  • 重み付き最短経路にはダイクストラ法が必要で、優先度付きキューを用いて未訪問の最小コスト頂点を展開する。

08貪欲法と最短経路

貪欲アルゴリズムは局所的に最良の選択にコミットし、決して見直さない。これは問題が最適部分構造と安全な貪欲選択を持つ場合に機能する: 活動選択は最も早く終わる両立可能な活動を選び、ハフマン符号化は最もまれな二つの記号を繰り返し併合する。

  • ダイクストラ法は貪欲な緩和である: 既知の距離が最小の未確定頂点を繰り返し確定し、その辺を緩和する。
  • 非負の重みが必要である; 負の辺がある場合はベルマン–フォード法を使い、これはすべての辺をn−1回緩和し、もう1回のパスで負閉路を検出する。
  • 貪欲アルゴリズムを正当化するよう求められたら、選択とそれがなぜ安全かを述べよ。
辺の緩和
\[d[v] = \min(d[v],\; d[u] + w(u,v))\]
uは確定済み、u→vは重みwの辺

09ソート、探索、Big-O

Big-Oは、定数や低次の項を無視して、コストが入力サイズとともにどのように増大するかを表す。これは成長率の言語であり、ストップウォッチではない: O(n²)のソートが小さな配列ではO(n log n)のソートに勝つことがあるのは、そのオーバーヘッドが小さいからである。

  • 比較ソートはΩ(n log n)を下回れない。
  • マージソートはO(n log n)を保証し、安定だが追加メモリを必要とする。
  • クイックソートは実際には高速だが、敵対的なピボットではO(n²)に劣化する。
  • 挿入ソートはほぼソート済みのデータに優れている。
  • 二分探索は各ステップで範囲を半分にするため、対数回の比較で済む。
二分探索の比較回数
\[C \le \lceil \log_2 n \rceil + 1\]
n個の要素からなるソート済み配列に対して
一般的な操作のコストと、それぞれが劣化する条件
操作構造典型的なコスト劣化する条件
添字によるアクセス配列O(1)添字が配列の範囲外
先頭への挿入連結リストO(1)まずノードを見つける必要がある

10成長率とマスター定理

漸化式は分割統治のコストを表し、マスター定理は分割・統合の仕事と葉で行われる仕事を比較することで、よくある形を解く。

  • 統合の項が支配的な場合、総コストは統合コストになる。
  • 葉が支配的な場合、葉のコストになる。
  • 両者が釣り合う場合、答えにはlogの因子が加わる。
  • 罠は代数ではなく記法にある: Oは上界、Ωは下界、Θはその両方を表し、これらは具体的な実行時間ではなく成長クラスを表す。
  • 試験前にlog n、√n、n、n log n、n²、2ⁿなどのクラスの順序を練習し、すべての答えを小さなケースで検証せよ。
マスター定理の形
\[T(n) = aT(n/b) + f(n)\]
f(n)とn^(log_b a)を比較する; より速く成長する方が総コストを決める
マスター定理を無理に適用しない これはT(n) = aT(n/b) + f(n)という形で、部分問題のサイズが等しい漸化式にのみ適用できる。不規則な分割の場合は、再帰木を描いて各レベルの和を求めよ。

11再帰と時間・メモリのトレードオフ

再帰関数はより小さな入力で自分自身を呼び出すことで問題を解く; 各呼び出しはコールスタックにフレームを追加するため、深さはメモリである。漸化式T(n) = 2T(n/2) + O(n)はO(n log n)に解け、一方、部分問題が繰り返される分岐する漸化式は指数関数的に爆発しうる。

  • 動的計画法は各部分問題を一度だけ格納することでその爆発を除去する。
  • メモ化はトップダウンの再帰を保ち結果をキャッシュする; ボトムアップ形式は依存順に表を埋める。
  • どちらも時間を得るためにメモリを使うので、実装前に漸化式に繰り返しの仕事がないか調べよ。
分割統治の漸化式
\[T(n) = 2T(n/2) + O(n) \rightarrow O(n\log n)\]
等しいサイズの二つの半分と線形の仕事
動的計画法の漸化式
\[r(n) = \max_{1 \le i \le n} (p(i) + r(n-i))\]
各部分問題は一度だけ解かれる

12トポロジカル順序と閉路検出

有向非巡回グラフ（DAG）は前提条件を持つタスクをモデル化し、トポロジカル順序はすべての辺が前方を指すように頂点を並べる。

  • カーンのアルゴリズムは入次数がゼロの頂点を繰り返し除去する; 頂点が残ったまま処理が止まれば、グラフは閉路を含む。
  • 深さ優先探索は終了時刻を逆順にすることで同じ順序を与える。
  • 閉路検出とトポロジカルソートは、プログラム、依存関係の集合、組立順序が実行可能であることを示す必要があるときに現れる。
  • スケジューリングの問題では、まず先行関係グラフを描き、入次数を計算し、キューをシミュレートせよ — 得られる順序は一つの有効な答えであり、必ずしも唯一のものではない。
入次数の更新
for each edge u→v: indegree[v] = indegree[v] − 1
uを除去した後; ゼロになった頂点はキューに入る

Worked example

連鎖法を用いたハッシュテーブルへの挿入

ハッシュテーブルはm = 7個のバケットを持ち、分離連鎖法でh(k) = k mod 7を用い、キー25、38、41、7、52、61、33、14をこの順に、それぞれの連鎖の先頭に追加しながら挿入する。最終的なテーブル、その負荷率、および38と61を見つけるのに必要な比較回数を示せ。

  1. 各キーのバケット添字: 25 → 4、38 → 3、41 → 6、7 → 0、52 → 3、61 → 5、33 → 5、14 → 0。
  2. 順に挿入し先頭に追加する: バケット4は25を持つ; バケット3は52 → 38に成長する; バケット6は41を持つ。
  3. バケット5は33 → 61に成長する。61が33より先に挿入され、先頭追加は新しいキーを先頭に置くためである。同じ理由でバケット0は14 → 7に成長する。
  4. 最終的な連鎖: バケット0: 14 → 7; バケット3: 52 → 38; バケット4: 25; バケット5: 33 → 61; バケット6: 41; バケット1と2は空。
  5. 負荷率α = 8/7 ≈ 1.14なので、平均連鎖長は1ノードより長く、最長連鎖は2ノードである。
  6. 38を探す: バケット3を調べ、52（不一致）、次に38（一致）と比較するので2回の比較。61を探す: バケット5を調べ、33、次に61と比較するので、これも2回の比較。
Answer連鎖は14 → 7（バケット0）、52 → 38（3）、25（4）、33 → 61（5）、41（6）であり、バケット1と2は空である。負荷率は8/7 ≈ 1.14で、どちらの探索も2回の比較で済む。1を超える負荷率はテーブルの拡張と再ハッシュを正当化し、それが期待されるO(1)の振る舞いを回復する。

Exam method

  • 最悪ケースと平均ケースを別々に示せ; ハッシュテーブルがO(1)なのは平均のみである。
  • 構造を使う前にその不変条件を述べよ — ヒープ順序、探索木順序、ソート済み配列 — なぜならすべての操作がそれに依存するからである。
  • 再帰については、まず漸化式を書き、次にマスター定理で解くか引用せよ; コードから成長率を推測してはならない。
  • ダイクストラ法では距離表を描き、確定される順に頂点に印を付けよ; 確定前の頂点から決して緩和してはならない。
