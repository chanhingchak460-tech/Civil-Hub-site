자료구조를 선택하는 것은 비용에 대한 결정이다. 이 페이지에서는 배열, 리스트, 스택, 큐, 해시 테이블, 트리, 그래프를 다루고, 그 다음 정렬, 검색, 그리고 이들을 비교하는 데 사용되는 Big-O 표기법을 다룬다.

01구조는 알고리즘의 일부이다

추상 데이터 타입은 계약이다: 연산과 그 의미를 정의하며, 구현에 대한 약속은 없다. 자료구조는 그 계약을 지키는 한 가지 방법이며, 모든 구현은 무언가를 맞바꾼다 — 시간을 메모리와, 또는 일반성을 속도와.

  • 값이 존재하는지 찾기: 정렬되지 않은 배열에서는 선형 스캔, 정렬된 배열에서는 로그 검색, 해시 테이블에서는 평균 상수 시간 조회.
  • 코드를 작성하기 전에 프로그램이 가장 자주 수행하는 연산을 먼저 파악하라.

02배열과 연결 리스트

배열은 요소를 연속된 메모리에 저장하므로 인덱싱은 상수 시간 산술이지만, 중간에 삽입하면 그 뒤의 모든 요소가 이동한다. 연결 리스트는 서로를 가리키는 노드를 저장한다: 알려진 노드에 삽입하는 것은 상수 시간이지만, 위치 k에 도달하려면 k개의 노드를 걸어야 하며, 각 단계는 캐시 미스가 발생할 수 있다.

  • 인덱스 읽기와 반복에는 배열을 사용하고, 무작위 접근 없이 이어붙이기와 재정렬에는 리스트를 사용하라.
  • 동적 배열은 용량을 두 배로 늘려 성장 비용을 분산시키므로, 추가(append)가 평균적으로 O(1)이 된다.

03스택과 큐

스택은 후입선출(LIFO)이다: 한쪽 끝에서 push와 pop을 한다. 이는 중첩 구조 — 함수 호출, 괄호 매칭, 깊이 우선 탐색, 실행 취소 기록 — 를 모델링한다. 큐는 선입선출(FIFO)이다: 뒤에서 enqueue하고 앞에서 dequeue한다. 이는 공정한 서비스와 너비 우선 탐색, 예를 들어 시작점으로부터의 거리 순으로 도로 네트워크를 탐색하는 것을 모델링한다.

  • 일반 배열 큐는 front가 전진하면서 공간을 낭비한다; 원형 버퍼는 이를 재사용한다.
  • 덱(deque)은 양쪽 끝에서 상수 시간 연산을 허용한다.

04해시 테이블

해시 테이블은 h(key)를 계산하여 키를 버킷에 매핑하며, 평균 상수 시간 조회, 삽입, 삭제를 목표로 한다. 충돌은 불가피하다; 분리 연결법은 버킷마다 리스트를 저장하고, 개방 주소법은 고정된 순서로 다른 슬롯을 탐사한다.

  • 성능은 저장된 키와 버킷의 비율인 부하율에 달려 있다.
  • 작은 테이블과 나쁜 해시 함수는 기대 O(1)을 O(n)으로 만든다.
  • 반복 순서에 의존하지 말고, 부하율이 임계값을 넘으면 두 배로 늘려 재해싱하라.
부하율
\[\alpha = \frac{n}{m}\]
m개의 버킷에 n개의 키; α를 약 0.75 이하로 유지하라

05트리와 힙

이진 탐색 트리는 작은 키를 왼쪽에, 큰 키를 오른쪽에 유지하므로 검색 비용은 트리의 높이이다: 균형일 때 O(log n), 퇴화했을 때 O(n). 균형 트리는 삽입 시 재균형을 수행하여 로그 높이를 보장한다.

  • 힙은 부분 순서만 유지한다 — 최소 힙의 경우 모든 부모가 자식보다 작다 — 이는 우선순위 큐에 충분하다.
  • push와 pop은 O(log n)이고, 극값 읽기는 O(1)이며, 구조는 평면 배열에 저장된다.

06균형과 회전

탐색 트리는 균형을 유지할 때만 로그 시간 복잡도를 가진다. AVL 트리는 모든 노드에서 두 서브트리의 높이 차이가 1 이내가 되도록 유지한다; 삽입이 이 규칙을 깨면 회전으로 복원한다.

  • 단일 회전은 바깥쪽이 무거운 형태를 고치고, 이중 회전은 지그재그 안쪽 형태를 고친다.
  • 회전은 국소적인 포인터 조작이다: 상수 시간이지만, 부모 링크와 저장된 높이를 갱신해야 한다.
  • 레드-블랙 트리는 규칙을 완화하여 삽입당 최대 상수 번의 회전만 필요로 하는 색상 체계를 사용한다.
  • 시험에서는 불변식을 먼저 명시하고, 두 번째로 회전을 적용하고, 세 번째로 메타데이터를 갱신하라.
AVL 균형 인수
\[\mathrm{BF} = h_L - h_R \in \{-1, 0, +1\}\]
삽입이나 삭제가 이를 깰 수 있다; 한두 번의 회전으로 복원한다
힙 배열 인덱스
children of i: 2i + 1 and 2i + 2; parent: (i − 1) // 2
이진 힙의 0 기반 배열 배치

07그래프와 탐색 방법

그래프는 정점과 간선으로 구성되며, 거리나 이동 시간에 대한 가중치를 가진다.

  • 인접 리스트는 정점별로 이웃을 저장하며 희소 네트워크에 적합하다.
  • 인접 행렬은 n² 메모리를 사용하고 "간선이 있는가?"를 상수 시간에 답하므로 밀집 그래프에 적합하다.
  • 너비 우선 탐색은 계층별로 탐색하며 모든 간선의 가중치가 같을 때 최단 경로를 찾는다.
  • 깊이 우선 탐색은 한 가지를 가능한 멀리 따라가며 사이클, 연결 요소, 위상 순서를 드러낸다.
  • 가중치 최단 경로에는 다익스트라 알고리즘이 필요하며, 이는 우선순위 큐를 사용하여 방문하지 않은 가장 저렴한 정점을 확장한다.

08탐욕 알고리즘과 최단 경로

탐욕 알고리즘은 국소적으로 최선의 선택을 확정하고 다시 돌아보지 않는다. 이는 문제가 최적 부분 구조와 안전한 탐욕적 선택을 가질 때 작동한다: 활동 선택은 가장 일찍 끝나는 호환 가능한 활동을 유지하고, 허프만 코딩은 가장 드문 두 기호를 반복적으로 병합한다.

  • 다익스트라 알고리즘은 탐욕적 완화이다: 알려진 거리가 가장 작은 미확정 정점을 반복적으로 확정한 다음, 그 간선을 완화한다.
  • 음이 아닌 가중치가 필요하다; 음의 간선이 있으면 벨만-포드 알고리즘을 사용하라. 이는 모든 간선을 n−1번 완화하고 추가 한 번의 패스로 음의 사이클을 감지한다.
  • 탐욕 알고리즘을 정당화하라는 요청을 받으면, 선택과 그것이 안전한 이유를 명시하라.
간선 완화
\[d[v] = \min(d[v],\; d[u] + w(u,v))\]
u는 확정되었고, u→v는 가중치 w의 간선이다

09정렬, 검색 및 Big-O

Big-O는 상수와 저차항을 무시하고 비용이 입력 크기에 따라 어떻게 증가하는지를 설명한다. 이는 성장률의 언어이지 스톱워치가 아니다: O(n²) 정렬이 작은 배열에서는 오버헤드가 더 작기 때문에 O(n log n) 정렬을 이길 수 있다.

  • 비교 정렬은 Ω(n log n)보다 빠를 수 없다.
  • 병합 정렬은 O(n log n)을 보장하고 안정적이지만 추가 메모리가 필요하다.
  • 퀵 정렬은 실제로 빠르지만 적대적인 피벗에서는 O(n²)으로 퇴화한다.
  • 삽입 정렬은 거의 정렬된 데이터에서 탁월하다.
  • 이진 검색은 각 단계에서 범위를 절반으로 줄이므로 로그 비교만 필요하다.
이진 검색 비교 횟수
\[C \le \lceil \log_2 n \rceil + 1\]
n개 요소의 정렬된 배열에 대해
일반적인 연산의 비용과 각각이 퇴화하는 경우
연산구조일반적 비용퇴화 조건
인덱스로 접근배열O(1)인덱스가 배열 범위를 벗어남
맨 앞에 삽입연결 리스트O(1)노드를 먼저 찾아야 함
키로 조회해시 테이블평균 O(1)높은 부하율 또는 클러스터링
검색균형 탐색 트리O(log n)트리가 퇴화함
정렬병합 정렬O(n log n)병합을 위한 추가 메모리

10성장률과 마스터 정리

점화식은 분할 정복 비용을 설명하며, 마스터 정리는 분할 및 결합 작업을 리프에서 수행되는 작업과 비교하여 일반적인 형태를 해결한다.

  • 결합 항이 지배적이면 전체는 결합 비용이다.
  • 리프가 지배적이면 리프 비용이다.
  • 둘이 균형을 이루면 답에 로그 인자가 추가된다.
  • 함정은 대수가 아니라 표기법이다: O는 상한, Ω는 하한, Θ는 둘 다이며, 이들은 특정 실행 시간이 아닌 성장 클래스를 설명한다.
  • 시험 전에 log n, √n, n, n log n, n², 2ⁿ과 같은 클래스의 순서를 연습하고, 모든 답을 작은 사례로 검증하라.
마스터 정리 형태
\[T(n) = aT(n/b) + f(n)\]
f(n)을 n^(log_b a)와 비교하라; 더 빠르게 성장하는 쪽이 전체를 결정한다
마스터 정리를 억지로 적용하지 말라 이는 T(n) = aT(n/b) + f(n) 형태의 점화식에만 적용되며, 동일한 크기의 부분 문제를 가정한다. 불규칙한 분할의 경우 재귀 트리를 그려 각 레벨을 합산하라.

11재귀와 시간-메모리 트레이드오프

재귀 함수는 더 작은 입력에 대해 자신을 호출하여 문제를 해결한다; 각 호출은 호출 스택에 프레임을 추가하므로 깊이는 메모리이다. 점화식 T(n) = 2T(n/2) + O(n)은 O(n log n)으로 해결되지만, 반복되는 부분 문제가 있는 분기 점화식은 지수적으로 폭발할 수 있다.

  • 동적 프로그래밍은 각 부분 문제를 한 번만 저장하여 그 폭발을 제거한다.
  • 메모이제이션은 하향식 재귀를 유지하고 결과를 캐시한다; 상향식 형태는 의존성 순서로 테이블을 채운다.
  • 둘 다 시간을 사기 위해 메모리를 사용하므로, 구현 전에 점화식에서 반복 작업을 검사하라.
분할 정복 점화식
\[T(n) = 2T(n/2) + O(n) \rightarrow O(n\log n)\]
동일한 크기의 두 절반과 선형 작업
동적 프로그래밍 점화식
\[r(n) = \max_{1 \le i \le n} (p(i) + r(n-i))\]
각 부분 문제는 한 번만 해결된다

12위상 순서와 사이클 감지

방향성 비순환 그래프(DAG)는 선행 조건이 있는 작업을 모델링하며, 위상 순서는 모든 간선이 앞으로 향하도록 정점을 나열한다.

  • 칸의 알고리즘은 진입 차수가 0인 정점을 반복적으로 제거한다; 정점이 남은 채로 프로세스가 중단되면 그래프에 사이클이 있다.
  • 깊이 우선 탐색은 역순 완료 시간을 통해 동일한 순서를 제공한다.
  • 사이클 감지와 위상 정렬은 프로그램, 의존성 집합 또는 조립 순서가 실현 가능함을 보여야 할 때마다 등장한다.
  • 스케줄링 질문의 경우, 선행 그래프를 먼저 그리고, 진입 차수를 계산하고, 큐를 시뮬레이션하라 — 얻은 순서는 하나의 유효한 답이며 반드시 유일한 것은 아니다.
진입 차수 갱신
for each edge u→v: indegree[v] = indegree[v] − 1
u를 제거한 후; 0이 되는 정점은 큐에加入한다

Key terms

추상 데이터 타입
구현과 독립적으로 연산과 그 동작을 명세한 것.
부하율
저장된 키의 수를 버킷의 수로 나눈 값; 해시 테이블 성능을 제어한다.
이진 탐색 트리
작은 키는 왼쪽에, 큰 키는 오른쪽에 두고 높이 시간에 검색하는 트리.
힙
부모와 자식 사이에 부분 순서를 가진 트리로, 우선순위 큐를 구현하는 데 사용된다.
Big-O
알고리즘 비용이 입력 크기에 따라 증가하는 방식에 대한 점근적 상한으로, 상수 인자는 무시한다.
동적 프로그래밍
중복되는 부분 문제의 답을 저장하고 재사용하여 문제를 해결하는 방법.
AVL 트리
각 노드의 왼쪽과 오른쪽 서브트리 높이 차이가 1 이내가 되도록 유지하는 자가 균형 이진 탐색 트리.
위상 순서
DAG의 정점을 모든 간선이 앞에서 뒤로 향하도록 나열한 선형 순서.
Worked example

체이닝을 사용한 해시 테이블 삽입

해시 테이블은 m = 7개의 버킷을 가지며, h(k) = k mod 7과 분리 연결법을 사용하고, 키 25, 38, 41, 7, 52, 61, 33, 14를 순서대로 삽입하며 각각을 해당 체인의 앞에 추가한다. 최종 테이블, 부하율, 그리고 38과 61을 찾는 데 필요한 비교 횟수를 보여라.

  1. 각 키의 버킷 인덱스: 25 → 4, 38 → 3, 41 → 6, 7 → 0, 52 → 3, 61 → 5, 33 → 5, 14 → 0.
  2. 순서대로 삽입하고 앞에 추가: 버킷 4는 25를 가진다; 버킷 3은 52 → 38로 성장한다; 버킷 6은 41을 가진다.
  3. 버킷 5는 33 → 61로 성장한다. 61이 33보다 먼저 삽입되었고 앞에 추가하면 새 키가 맨 앞에 오기 때문이다. 버킷 0은 같은 이유로 14 → 7로 성장한다.
  4. 최종 체인: 버킷 0: 14 → 7; 버킷 3: 52 → 38; 버킷 4: 25; 버킷 5: 33 → 61; 버킷 6: 41; 버킷 1과 2는 비어 있다.
  5. 부하율 α = 8/7 ≈ 1.14이므로 평균 체인은 한 노드보다 길고 가장 긴 체인은 두 노드를 가진다.
  6. 38 찾기: 버킷 3을 탐사하고, 52를 비교(미스), 그 다음 38(히트)이므로 두 번 비교한다. 61 찾기: 버킷 5를 탐사하고, 33을 비교, 그 다음 61, 역시 두 번 비교한다.
Answer체인은 14 → 7 (버킷 0), 52 → 38 (3), 25 (4), 33 → 61 (5), 41 (6)이며; 버킷 1과 2는 비어 있다. 부하율은 8/7 ≈ 1.14이고, 두 검색 모두 두 번의 비교가 필요하다. 1보다 큰 인자는 테이블을 확장하고 재해싱할 정당성을 제공하며, 이는 기대 O(1) 동작을 복원한다.

Exam method

  • 최악의 경우와 평균적인 경우를 별도로 제시하라; 해시 테이블은 평균적으로만 O(1)이다.
  • 구조를 사용하기 전에 불변식을 명시하라 — 힙 순서, 탐색 트리 순서, 정렬된 배열 — 모든 연산이 이에 의존하기 때문이다.
  • 재귀의 경우 점화식을 먼저 작성한 다음 해결하거나 마스터 정리를 인용하라; 코드에서 성장률을 추측하지 말라.
  • 다익스트라의 경우 거리 테이블을 그리고 정점이 확정되는 순서대로 표시하라; 정점이 확정되기 전에 완화하지 말라.
