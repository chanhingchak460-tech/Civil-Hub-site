選擇資料結構，其實就係一個關於成本嘅決定。呢頁會講陣列、鏈結串列、堆疊、佇列、雜湊表、樹同圖，然後講排序、搜尋，以及用嚟比較佢哋嘅 Big-O 語言。

進度只儲存在此瀏覽器。

01結構係演算法嘅一部分

抽象資料型別係一份合約：講明有咩操作同埋佢哋嘅意義，但唔承諾點樣實作。資料結構係履行呢份合約嘅其中一種方式，而每種實作都要犧牲啲嘢——用時間換記憶體，或者用通用性換速度。

  • 搵一個值存唔存在：喺未排序嘅陣列做線性掃描，喺已排序嘅陣列做對數搜尋，喺雜湊表做平均常數時間查詢。
  • 寫程式之前，先講清楚程式最常做嘅操作係邊啲。

02陣列同鏈結串列

陣列將元素存放喺連續記憶體，所以索引係常數時間嘅算術運算，但喺中間插入就要將後面嘅嘢全部移位。鏈結串列存放互相指向嘅節點：喺已知節點插入係常數時間，但要去到位置 k 就要行 k 個節點，而且每一步都可能 miss cache。

  • 需要索引讀取同迭代就用陣列；需要拼接同重排而唔使隨機存取就用串列。
  • 動態陣列透過容量倍增嚟攤銷擴張成本，令附加操作平均係 O(1)。

03堆疊同佇列

堆疊係後入先出：喺同一端 push 同 pop。佢模擬嵌套結構——函式呼叫、括號配對、深度優先遍歷、復原歷史。佇列係先入先出：喺尾 enqueue，喺頭 dequeue。佢模擬公平服務同廣度優先遍歷，例如按距離起點嘅遠近去探索道路網絡。

  • 普通陣列佇列會隨住前端推進而浪費空間；環形緩衝區可以重用返。
  • 雙端佇列可以喺兩端都以常數時間操作。

04雜湊表

雜湊表透過計算 h(key) 將鍵映射到桶，目標係平均常數時間嘅查詢、插入同刪除。碰撞無可避免；分離鏈結喺每個桶存一條串列，而開放定址就按固定序列探測其他槽位。

  • 效能取決於負載因子，即已存鍵數同桶數嘅比率。
  • 細表同差嘅雜湊函式會令預期 O(1) 變成 O(n)。
  • 永遠唔好依賴迭代次序，負載因子過咗門檻就要倍增容量並重新雜湊。
負載因子
\[\alpha = \frac{n}{m}\]
m 個桶入面有 n 個鍵；將 α 保持喺大約 0.75 以下

05樹同堆

二元搜尋樹將較細嘅鍵放左邊、較大嘅鍵放右邊，所以搜尋成本等於樹高：平衡時係 O(log n)，退化時係 O(n)。平衡樹喺插入時重新平衡，保證對數高度。

  • 堆只維持部分次序——最小堆入面每個父節點都細過佢嘅子節點——咁就已經夠用嚟做優先佇列。
  • Push 同 pop 成本係 O(log n)，讀取極值成本係 O(1)，而個結構住喺一個平坦陣列入面。

06平衡同旋轉

搜尋樹只有喺保持平衡時先係對數。AVL 樹喺每個節點都要求兩棵子樹嘅高度相差唔超過一；當插入破壞咗呢條規則，就用旋轉修復。

  • 單旋轉修復外側偏重嘅形狀，雙旋轉就修復內側之字形嘅形狀。
  • 旋轉係局部嘅指標手術：常數時間，但必須更新父連結同儲存嘅高度。
  • 紅黑樹將規則放寬成一種著色方案，每次插入最多只需要常數次旋轉。
  • 考試時，先講出不變量，再做旋轉，最後更新元數據。
AVL 平衡因子
\[\mathrm{BF} = h_L - h_R \in \{-1, 0, +1\}\]
插入或刪除可能會破壞佢；一或兩次旋轉就可以修復
堆陣列索引
children of i: 2i + 1 and 2i + 2; parent: (i − 1) // 2
二元堆嘅零基陣列佈局

07圖同點樣行佢哋

圖係頂點加邊，邊可以帶權重代表距離或行車時間。

  • 鄰接表為每個頂點儲存鄰居，適合稀疏網絡。
  • 鄰接矩陣用 n² 記憶體，以常數時間回答「有冇邊？」，適合稠密網絡。
  • 廣度優先搜尋按層探索，當每條邊權重相同時可以搵到最短路徑。
  • 深度優先搜尋沿一條分支行到盡，揭示環、連通分量同拓撲次序。
  • 帶權最短路徑需要 Dijkstra 演算法，佢用優先佇列擴展最便宜嘅未訪問頂點。

08貪心演算法同最短路徑

貪心演算法承諾局部最佳選擇，而且唔會回頭。當問題具備最優子結構加上安全嘅貪心選擇時就有效：活動選擇保留最早完結嘅相容活動，Huffman 編碼就反覆合併最罕見嘅兩個符號。

  • Dijkstra 演算法係貪心鬆弛：反覆確定已知距離最細嘅未確定頂點，然後鬆弛佢嘅邊。
  • 佢要求非負權重；有負邊就用 Bellman–Ford，佢將每條邊鬆弛 n−1 次，並喺多一次遍歷中偵測負環。
  • 被要求論證貪心演算法時，講出選擇同埋點解佢係安全。
邊鬆弛
\[d[v] = \min(d[v],\; d[u] + w(u,v))\]
u 已確定，u→v 係權重為 w 嘅邊

09排序、搜尋同 Big-O

Big-O 描述成本點樣隨輸入規模增長，忽略常數同低階項。佢係一套增長率嘅語言，唔係秒錶：O(n²) 排序喺細陣列上可能贏 O(n log n) 排序，因為佢嘅額外開銷較細。

  • 比較排序唔可以快過 Ω(n log n)。
  • 合併排序保證 O(n log n) 而且穩定，但需要額外記憶體。
  • 快速排序實際好快，但喺惡意樞軸下會退化到 O(n²)。
  • 插入排序喺近乎已排序嘅資料上表現極佳。
  • 二元搜尋每一步將範圍減半，所以只需要對數次比較。
二元搜尋比較次數
\[C \le \lceil \log_2 n \rceil + 1\]
對於 n 個元素嘅已排序陣列
常見操作嘅成本同各自喺幾時退化
操作結構典型成本幾時退化
按索引存取陣列O(1)索引超出陣列範圍
喺頭部插入鏈結串列O(1)要先搵到嗰個節點
按鍵查詢雜湊表平均 O(1)負載因子高或者聚集
搜尋平衡搜尋樹O(log n)棵樹退化
排序合併排序O(n log n)合併需要額外記憶體

10增長率同主定理

遞迴式描述分治成本，而主定理透過比較分割合併嘅工作量同葉子嘅工作量，解決常見形狀。

  • 當合併項主導，總量就係合併成本。
  • 當葉子主導，就係葉子成本。
  • 當兩者平衡，答案就多一個對數因子。
  • 陷阱係符號而唔係代數：O 係上界，Ω 係下界，Θ 係兩者，而佢哋描述嘅係增長類別，唔係具體執行時間。
  • 考試前練習排序 log n、√n、n、n log n、n² 同 2ⁿ 等類別，並用細案例檢查每個答案。
主定理形狀
\[T(n) = aT(n/b) + f(n)\]
將 f(n) 同 n^(log_b a) 比較；邊個增長得快就決定總量
唔好硬套主定理 佢只適用於 T(n) = aT(n/b) + f(n) 形狀、子問題大小相等嘅遞迴式。對於唔規則嘅分割，改為畫遞迴樹並將各層加總。

11遞迴同時間與記憶體嘅取捨

遞迴函式透過喺更細嘅輸入上呼叫自己嚟解決問題；每次呼叫都會喺呼叫堆疊加一個框架，所以深度就係記憶體。遞迴式 T(n) = 2T(n/2) + O(n) 解得 O(n log n)，而帶重複子問題嘅分支遞迴式可以指數爆炸。

  • 動態規劃透過將每個子問題只存一次嚟消除呢種爆炸。
  • 記憶化保留由上而下嘅遞迴並快取結果；由下而上嘅形式就按依賴次序填表。
  • 兩者都用記憶體換時間，所以實作之前要檢查遞迴式有冇重複工作。
分治遞迴式
\[T(n) = 2T(n/2) + O(n) \rightarrow O(n\log n)\]
兩個等大嘅半邊加線性工作
動態規劃遞迴式
\[r(n) = \max_{1 \le i \le n} (p(i) + r(n-i))\]
每個子問題只解一次

12拓撲次序同環偵測

有向無環圖（DAG）模擬有前置條件嘅任務，而拓撲次序將頂點排成一列，令每條邊都指向前方。

  • Kahn 演算法反覆移除入度為零嘅頂點；如果過程停低而仲有頂點剩返，個圖就含有環。
  • 深度優先搜尋透過反轉完成時間得出相同次序。
  • 每當要證明一個程式、一組依賴或者一個裝配序列可行，就會出現環偵測同拓撲排序。
  • 排程問題方面，先畫優先圖，計入度，再模擬佇列——得出嘅次序係其中一個有效答案，未必係唯一。
In-degree update
for each edge u→v: indegree[v] = indegree[v] − 1
after removing u; any vertex reaching zero joins the queue

計算示例

插入有鏈結嘅雜湊表

一個雜湊表有 m = 7 個桶，用 h(k) = k mod 7 同分離鏈結，並按次序插入鍵 25、38、41、7、52、61、33 同 14，每個都前置到佢嘅鏈。展示最終表格、佢嘅負載因子，以及搵 38 同 61 所需嘅比較次數。

  1. 每個鍵嘅桶索引：25 → 4，38 → 3，41 → 6，7 → 0，52 → 3，61 → 5，33 → 5，14 → 0。
  2. 按次序插入並前置：桶 4 存 25；桶 3 變成 52 → 38；桶 6 存 41。
  3. 桶 5 變成 33 → 61，因為 61 喺 33 之前插入，而前置會將新鍵放喺最前。桶 0 出於同樣原因變成 14 → 7。
  4. 最終鏈：桶 0：14 → 7；桶 3：52 → 38；桶 4：25；桶 5：33 → 61；桶 6：41；桶 1 同 2 係空嘅。
  5. 負載因子 α = 8/7 ≈ 1.14，所以平均鏈長過一個節點，而最長鏈有兩個節點。
  6. 搵 38：探測桶 3，比較 52（唔中），然後 38（中），所以兩次比較。搵 61：探測桶 5，比較 33，然後 61，都係兩次比較。
Answer鏈係 14 → 7（桶 0）、52 → 38（3）、25（4）、33 → 61（5）同 41（6）；桶 1 同 2 係空嘅。負載因子係 8/7 ≈ 1.14，而兩個搜尋都係兩次比較。因子大過 1 就值得擴張表格並重新雜湊，咁就可以恢復預期 O(1) 行為。

應試方法

  • 最壞情況同平均情況要分開講；雜湊表只係平均 O(1)。
  • 用結構之前先講出不變量——堆次序、搜尋樹次序、已排序陣列——因為每個操作都依賴佢。
  • 遞迴方面，先寫遞迴式，然後求解或者引用主定理；唔好從程式碼猜增長率。
  • Dijkstra 方面，畫距離表並按確定次序剔頂點；頂點未確定之前永遠唔好由佢鬆弛。

Q02邊種結構最自然用嚟實作圖嘅廣度優先搜尋？

解釋BFS 按頂點被發現嘅次序訪問佢哋，所以先入先出嘅佇列可以令邊界保持正確次序。

解釋重複子問題只解一次並快取，可以將指數工作變成多項式工作，代價係記憶體。

解釋Dijkstra 依賴已確定嘅距離之後永遠唔會改善，負邊可以破壞呢點；Bellman–Ford 就處理負權重。
