創新與創業

將工程構思轉化為人實際使用的產品

一個技術構思如何變成真正有人使用的東西：尋找真實問題、低成本測試、塑造價值主張與商業模式。這是工程項目背後的商業語法。

進度只儲存在此瀏覽器。

01創新不是發明

發明是一個新構思；創新是將該構思變得有用、被採用並重複使用。從未離開實驗室的專利是發明。工地團隊每天使用的廉價感測器網絡是創新。

  • 大多數創新是漸進式的：更好的接頭、更快的檢查、更精簡的配合比。
  • 顛覆性創新改變整個市場的成本或可及性，而不僅僅是產品的性能。
  • 漸進式構思需要測試和反饋；顛覆性構思需要保護和耐心。

02從問題出發

工程項目通常始於一種尋找用途的技術；創業項目則始於一個人及其困難。有用的問題不是「我們能建造什麼？」而是「誰的工作比應有的更困難，為什麼？」

觀察勝於假設。觀察人們如何完成任務，注意他們發明的變通方法，並詢問出錯時他們損失什麼——時間、金錢、安全或聲譽。每週重複出現的痛點勝過聽起來聰明的功能。同理心地圖組織第一輪訪談。

同理心地圖
Says · Thinks · Does · Feels
從觀察而非猜測填寫全部四個象限

03設計思維作為循環

設計思維降低建造錯誤東西的風險。它經歷同理心理解用戶、定義問題、產生替代方案、建造粗略原型並與真實用戶測試。循環重複；不是單次通過。

定義步驟是大多數項目失敗的地方。「工地主管無法在工人閒置前看到哪些交付延誤」是可測試的。「提高施工效率」則不是。早期廉價原型比後期精美計劃更有價值。

設計思維循環
Empathise → Define → Ideate → Prototype → Test → repeat
每個循環應回答一個問題

04價值主張與商業模式

價值主張說明客戶是誰、他們需要完成什麼工作，以及為什麼你的提供比替代方案更好。你緩解的痛點和創造的收益應各自與特定用戶相關。

商業模式回答更難的問題：誰付費、以什麼單位、多久一次，以及交付成本是多少。工程公司銷售專業知識和保證而非物件，因此模式通常是收費制和聲譽驅動。

新創企業的兩個視角
問題價值主張商業模式
為誰而設？一個特定用戶群體付費客戶，可能不同
什麼問題？需要完成的工作銷售的價值單位
為什麼是你？更好結果的證據成本優勢或防禦性
如何持續？未涉及收入、成本、可重複性

05建築中的智慧城市技術

技術層是土木工程與數據交匯之處。廉價的IoT感測器報告溫度、振動、粉塵、水位或設備工時，對故障泵、養護中的混凝土或禁區內的工人提供更早預警。人工智能增加模式發現：預測性維護、標記不安全序列，以及根據天氣和交付調整的進度。區塊鏈更多涉及記錄而非現場工作——材料和證書的可審計保管鏈。

採用是困難的部分。沒有備用電源的感測器在火災中失效，虛報的警報會被關閉。技術只有在可靠、維護並與某人負責的決策相關聯時才能贏得信任。

06從構思到企業

最小可行產品是能產生真實反饋的最小版本：登陸頁面、紙質原型、單一試點工地。它是為了學習而建，不是為了打動人。

資金跟隨證據。許多企業始於創始人儲蓄和早期客戶付款，然後隨著牽引力出現轉向補助金、競賽或天使投資。每個來源都以代價換取時間：股權、報告義務或限制。團隊還需要法律結構、會計、保險和監管視角。大多數首次創業失敗於需求疲弱或現金耗盡，這就是為什麼快速、誠實的反饋勝過完美計劃。

07商業模式畫布

商業模式畫布強迫企業在一頁紙上回答九個相互關聯的問題：客戶是誰、他們獲得什麼價值、通過哪些渠道和關係、哪些活動、資源和合作夥伴來交付、收入如何到達以及成本是什麼。

填寫區塊會暴露漏洞——擁有出色價值主張但沒有成本故事的團隊只有半個模型。區塊是相互關聯的。改變客戶細分，渠道、收入和成本區塊必須隨之改變。將畫布作為整體審查，而非逐塊審查。

九個畫布區塊分組
組別區塊回答的問題
客戶客戶細分、渠道、關係誰購買，如何接觸和保留？
提供價值主張為他們完成什麼工作？
交付關鍵活動、關鍵資源、關鍵合作夥伴必須存在什麼才能交付？
金錢收入來源、成本結構金錢如何流入和流出？

08單位經濟與收支平衡

企業可以受歡迎但仍然失敗，因此將模型轉化為數字。單位經濟跟隨一次銷售：收入 R = p × q，其中 p 是價格，q 是銷售數量。固定成本 F 即使沒有銷售也存在；可變成本 v 隨每單位變化。收支平衡數量是覆蓋一切的單位數量：q_BE = F / (p − v)。

如果監測服務以每單位月 200 銷售，可變成本 80，固定成本 120,000，收支平衡為 1,000 單位月。早期計算數字顯示價格、成本和市場規模能否滿足。

收入
\[R = p \times q\]
每單位價格乘以銷售數量
收支平衡數量
\[q_{BE} = \frac{F}{p - v}\]
F 固定成本，p 價格，v 每單位可變成本

09推介與請求

推介是決策，不是講座。可靠的弧線是問題、解決方案、市場、商業模式、牽引力、團隊和請求——具體金額、用途、時間。

證據勝過形容詞：一個有測量結果的試點工地勝過一頁聲明。先練習兩分鐘版本，因為每個更長的推介都是它的擴展。預測三個最難的問題——為什麼現在、為什麼是你、為什麼大公司不會複製——並為每個準備一句話。

推介弧線
Problem → Solution → Market → Model → Traction → Ask
以具體請求結束，而非模糊邀請

10保護構思

當價值可以被複製時，知識產權很重要。專利在固定期限內保護新穎技術解決方案，但耗費時間和金錢；版權保護代碼和圖紙等創意表達；商標保護名稱和標誌；商業秘密保護從未披露的內容。

許多工程企業更多依賴速度、關係和聲譽而非專利。及早決定保護，因為披露會破壞某些權利——公佈設計可能阻止後續專利。並在假設構思屬於你之前，檢查為客戶或僱主所做工作的所有權。

計算示例

為工地安全感測器撰寫價值主張

一個團隊提出可穿戴接近感測器，警告工人靠近重型機械。為與中型承包商進行的試點撰寫簡短價值主張和商業模式草圖。

  1. 命名用戶：有移動機械的項目中的工地主管和安全主任。
  2. 命名工作和痛點：讓工人遠離機械的旋轉半徑，目前依賴無法同時觀察每個角度的信號員。
  3. 陳述提供和證據：當被標記的工人進入地理圍欄時振動的手腕單元，在一個工地試點並通過未遂事件報告判斷。
  4. 草擬誰付費及如何持續：承包商為試點支付每單位月費；續約取決於更少的未遂事件和更清潔的安全記錄。
Answer對於有重型機械項目中的工地主管，他們無法同時觀察每個旋轉半徑，手腕單元在機械進入禁區前警告工人，使用地理圍欄而非一個人的視線；承包商為試點支付每單位月費，續約取決於更少的未遂事件和更好的安全記錄。

應試方法

  • 在舉例前用一句話定義創新；從未被採用的發明不是創新。
  • 在案例問題中，分開問題、用戶、解決方案和商業模式——評分者尋找所有四者。
  • 將每個主張錨定到一個具體用戶和一個具體痛點，而非一般社會效益。
  • 對於任何技術答案，除了效益外，還要添加採用障礙和保障措施。
  • 始終將商業模式轉化為數字：收入、成本和收支平衡數量顯示故事能否閉環。
