01品質は検査で作り込むのではなく、計画するもの

品質マネジメントシステムとは、品質を偶然ではなく再現可能なものにするための責任、手順、記録の集合である。それはプロセスループで運用される：要求事項を合意し、それをどのように達成するかを計画し、作業を行い、結果を仕様と照合して確認し、ギャップに対処する。

  • 品質保証は予防である — 施工方法書、モックアップ、訓練、サプライヤー評価、設計チェック。
  • 品質管理は検出である — 合否判定基準に対する検査、試験、測定。
  • 管理のみに依存するプロジェクトは、自らの誤りを見つけるために費用を払っていることになる。
  • 品質コストは、そのトレードオフを可視化する方法である。

02検査・試験計画

検査・試験計画（ITP）は、各作業について、何を、どの合否判定基準に対して、誰が、どの頻度で確認し、その実施を証明する記録は何かを一覧化する。作業開始前に作成され、施工順序に従うため、品質プログラムとしても機能する。

  • ホールドポイント：検査に合格し署名されるまで作業を続けられない。
  • ウィットネスポイント：検査員は招かれるが、作業は続行してよい。
  • ITPの作成はリスクを考える作業である：後から発見すると高くつく、または危険な箇所をホールドし、それ以外をウィットネスとする。

03検査、試験、不適合

検査は作業に沿って行われる：納入材料に対する受入検査、施工中の工程内検査、引き渡し前の最終検査。試験は破壊試験（供試体、コア）または非破壊試験（かぶり厚計、反発硬度計、超音波、半電池電位）であり、結果は方法とサンプリング計画なしではほとんど意味を持たない。

何かが不合格となった場合の対応は不適合報告書である：
- 対象を隔離する
- 事実を記録する
- 処置（手直し、補修、特認による受入れ、または拒否）を合意する
- 根本原因を特定する
- 是正処置を完了する

各報告書を孤立した苦情として扱うとパターンが見えなくなる。職種別や場所別にグループ化することが改善の要点である。

04品質管理の七つ道具

七つの簡単なツールが、品質エンジニアが必要とする分析の大半を担う。

  • チェックシートは事象が発生するたびに件数を収集する。
  • ヒストグラムは測定値のばらつきを示す。
  • パレート図は欠陥原因を頻度順に並べ、重要な少数を先に取り組めるようにする。
  • 特性要因図は結果を材料、方法、人、設備、環境にさかのぼって追跡する。
  • 散布図は二つの変数が連動するかを検証する。
  • 管理図は時間を通じた普通原因変動と特殊原因を分離する。
  • フローチャートはプロセスを図示し、改善できるようにする。

これらのツールが安価なのは誠実さで動くからである：データが作業現場で収集され、それを生み出したプロセスでラベル付けされ、実際に対処されて初めて機能する。分類されていない欠陥のパレート図は絵であって意思決定ではない。

七つ道具とそれぞれが答える問い
ツール答える問い
チェックシート各事象はどのくらいの頻度で発生するか？
ヒストグラム測定値はどのように分布しているか？

特性要因図この結果を引き起こしている可能性は何か？

管理図プロセスは安定しているか、管理外か？

05工程能力と管理限界

管理状態にあるプロセスが自動的に能力があるとは限らない。管理限界はプロセスが実際に何をしているかを示し、規格限界は顧客が受け入れる範囲を示す。サンプル平均を管理限界に対してプロットするとドリフトや特殊原因が明らかになり、能力指数は自然なばらつきを公差と比較する。

  • Cpはばらつきが公差に収まるかを問う。
  • Cpkはさらにプロセスが中心にあるかを問う。
  • Cpが1.33超でCpkが0.6付近なら、プロセスは安定しているが狙いが大きく外れている — 検査頻度ではなく設定を調整すべきである。

次にサンプリング計画が、必要な信頼度に対して何個を試験するかを決める。だからこそ合否判定基準は常に方法とサンプリング率を一対で示す。

Process capability
\[C_p = \frac{\mathrm{USL} - \mathrm{LSL}}{6\sigma}\]
USL and LSL are the specification limits and σ the process standard deviation
Centred capability
\[C_{pk} = \min\left(\frac{\mathrm{USL} - \mu}{3\sigma},\, \frac{\mu - \mathrm{LSL}}{3\sigma}\right)\]
the smaller side rules; centring matters as much as spread
Control limits for sample means
\[\bar{x} \pm \frac{3\sigma}{\sqrt{n}}\]
for samples of size n; a point outside suggests a special cause

06MiCとDfMAは品質を工場へ移す

モジュラー統合建設（MiC）と製造・組立のための設計（DfMA）は、作業を現場から管理された工場へ移す。モジュールは仕上げ、設備、時には建具まで取り付けた状態で到着するため、品質問題の形が変わる：繰り返しは一貫性を高め検査を容易にするが、設計はより早く凍結する必要があり、公差は正直に積み上げなければならず、モジュールと現場構造のインターフェースが新たなリスクとなる。

品質はその後、治具、モックアップ、工場検査計画、デジタル記録、トレーサビリティ、さらに輸送・吊り上げ中の保護に依存する。現場での作業は接続、シーリング、位置合わせであり、これら少数の作業が不釣り合いなほど大きなリスクを負う。

07BIMコーディネーションと共通データ環境

BIMは情報が信頼できる場合にのみ有用である。コーディネーションは分野別モデルを統合し、干渉チェックを実行し、現場での争いになる前にインターフェースを解決する。モデルは数量、施工順序、墨出しも支援する。

情報は共通データ環境（CDE）を通じて交換され、明確な状態 — 作業中、共有、公開、アーカイブ — に加えて命名、改訂、ステータスコードを持つ。未承認のモデルから施工してはならない。引き渡し時にモデルはアセット情報モデルとなり、運用が必要とするデータは最後に再構築するのではなく、最初に要求しなければならない。

08BIMデータ品質とデジタルQA/QC

デジタルQA/QCはモデルを他の成果物と同様に扱う。

  • ビジュアルチェックは形状と表示を検査する。
  • 整合性チェックはプロパティが定義され、妥当で、一意であることを確認する。
  • ルールベースのチェックは、合意された各目的に対して必要な情報が存在することを検証する。

命名とステータスコードはチェックを自動化可能にする — 名前のないファイルはその成果物に対してチェックできない。モジュール作業では同じ規律がモジュールに適用される：QRコード識別子、各ホールドポイントでの工場写真、養生や輸送条件のセンサー値、モデルにリンクしたデジタル記録。要点はトレーサビリティである：現場で欠陥が現れたとき、記録はモジュール、そのロット、検査員、試験結果を一度の検索で特定できるべきであり、一週間のアーカイブ探しではない。

チェックはスケジュールで実行する モデルチェックは各情報交換の前と各作業期間の終わりに予定され、プロジェクト終了時に一度だけ行うものではない。

09ステージ、役割、引き渡し

プロジェクトは要求、実現可能性・設計、入札、施工、試運転調整、引き渡し、運用へと進む。各ステージは次のステージが依存する情報の受け渡しで終わる。だからこそ後期の変更は高くつく：すでに確認済みの作業が無効になるからである。

役割は意図的に分離される：
- 発注者は要求事項を設定する。
- プロジェクトマネージャーは時間、コスト、コーディネーションを管理する。
- 設計者は仕様を書く。
- 施工者は計画し建設する。
- 監理者または現場監督は独立して検査する。
- 数量測量士はコストを管理する。

引き渡しには完全な一式 — 竣工記録、試験証明書、保証書、運用マニュアル、訓練 — が必要であり、瑕疵担保期間は粗悪な施工がコストとして戻ってくる場である。

10契約、記録、引き渡しの証拠

品質上の義務は仕様書と同じくらい契約書に存在する。モデルデータとその知的財産権を誰が所有するか、共有情報に誰が依拠できるか、確認済みの成果物が誤っていた場合にどうなるかは、紛争後に発見するのではなく委任文書に明記しなければならない。明確な起草はモデルを調整の道具として保ち、請求の源にしない。

記録は証拠である：検査シート、試験証明書、納品チェックリスト、写真は命名され、日付が付され、要素にリンクされ、引き渡し時に取得可能であるべきである。完全で構造化された記録一式は双方を保護し、それ自体が成果物である。契約が沈黙している場合、CDEルールと責任マトリクスが事実上の契約となる — それらを慎重に書くこと。

11工程の信頼性と日々の規律

品質は技術的問題と同じくらい工程の問題である。タスク、担当者、日付を明記した週次計画、今後数週間のルックアヘッド、実際に行われたことの日報がフィードバックループを形成する。

計画達成率は約束された作業が計画通りにどれだけ完了したかを測る。低い値は混乱、手直し、慌ただしい終盤を予測する。リスクも同じように管理する：記録し、評価し、担当者を割り当て、レビューする。一度書いて二度と開かないリスク登録簿は飾りである。

品質コスト
CoQ = prevention + appraisal + failure
計画達成率
\[\mathrm{PPC} = \frac{\text{completed tasks}}{\text{planned tasks}} \times 100\%\]
リスクスコア
\[\text{risk} = \text{likelihood} \times \text{consequence}\]

Worked example

モジュラープロジェクトにおける品質コスト

300モジュールのボリューメトリックモジュラープロジェクトで、建設予算は9,600万香港ドルである。12モジュールが工場で不合格となり、納品前に1個あたり9,500香港ドルで手直しされた。検査・試験費は18万香港ドル、モックアップ、訓練、工場監査などの予防活動費は12万香港ドルである。品質コスト、予算に対する割合、失敗に起因する割合を求めよ。

  1. 不合格モジュールは引き渡し前に発見されたため、そのコストは内部失敗である：12 × 9,500香港ドル = 114,000香港ドル。
  2. 予防＋評価 = 120,000香港ドル + 180,000香港ドル = 300,000香港ドル。
  3. 品質コスト = 予防 + 評価 + 失敗 = 300,000香港ドル + 114,000香港ドル = 414,000香港ドル。
  4. 予算に対する割合：414,000 / 96,000,000 = 0.0043、すなわち約0.43%。
  5. 失敗の割合 = 114,000 / 414,000 = 27.5%、一方予防は全体の29.0%である。
  6. 妥当性確認：同じ欠陥が引き渡し後に発見されれば外部失敗となり、補修、アクセス、責任のコストを伴うため、0.43%は下限であり真の最悪ケースではない。
Answer品質コストは414,000香港ドルで、建設予算の約0.43%であり、そのうち27.5%が失敗コストである。この比率は、工場出荷時に不合格品を見つけるよりも予防により多くの価値がある可能性を示唆している。

Exam method

  • 保証と管理の違いを学び、それぞれについてプロジェクトの例を挙げられるようにすること。
  • ITPの設問では、作業名だけでなく、必ず合否判定基準と記録を述べること。
  • 不適合の設問では、隔離、処置、根本原因を分けて考えること。配点は通常、段階ごとに割り当てられる。
  • 予防が補修より安い理由を問われたら品質コストの区分を用い、失敗の割合を示すこと。
  • CpとCpkを示すときは、それぞれが何を測るかを述べること：Cpは公差に対するばらつきを試し、Cpkは中心のずれを加味する — Cpが高くCpkが低い場合は、限界ではなくプロセスをずらすべきである。

Q01検査・試験計画におけるホールドポイントの機能は何か？

Whyホールドポイントは停止点である：文書化された検査の合格後にのみ次の段階が解放される。

Q02完成したモジュールの欠陥が建物の引き渡し後に発見された。このコストはどれに属するか：

Why顧客または供用中に発見される失敗は外部失敗であり、アクセス、責任、評判のコストが加わるため最も高価な区分である。

Q03共通データ環境において、施工が承認された情報を示す状態はどれか？

Why公開情報は確認と承認を経ている。作業中および共有状態は施工承認されていない。

Q04モジュラー建設に最も特徴的な品質リスクはどれか？

Why工場の繰り返しはよく管理されるが、モジュール間およびモジュールと構造間のインターフェースが残るリスクを現場に集中させる。

Q05パレート図は何のために用いるか：

Whyパレート図は原因を頻度の多い順から少ない順に並べ、大半の欠陥を生む少数の原因に努力を向ける。

Q06Cp = 1.5だがCpk = 0.5である。このプロセスは最も適切には：

WhyCpはばらつきが公差に余裕をもって収まることを示すが、Cpkはプロセス平均が目標から大きく離れていることを明らかにするため、中心合わせが問題である。
