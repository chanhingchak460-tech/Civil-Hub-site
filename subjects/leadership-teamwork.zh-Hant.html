人們實際上如何合作：溝通迴路、同理心與「我」訊息、每個團隊必經的階段，以及讓衝突保持有用的回饋。工程項目是由團隊交付，而非靠計算。

進度只儲存在此瀏覽器。

01溝通就是工作

在項目中，大多數失敗並非計算錯誤，而是資訊失效：沒有人開啟的圖紙修訂、在會議上提出但從未記錄的風險、誤解工序的工人。

溝通是一項技術技能，而非性格特質。發送者將訊息編碼，選擇渠道，接收者解碼，回饋閉合迴路。噪音——行話、嘈雜的工地、倉促的訊息——在每個階段都會介入。

沒有回饋的單向廣播不是溝通，而是公告。

溝通迴路
Sender → Message → Channel → Receiver → Feedback
噪音在每個階段起作用，直到回饋證明並非如此

02同理心與「我」訊息

同理心是在回應之前嘗試理解他人的立場。通常分為：

  • 情感同理心（對情緒產生感受反應）
  • 認知同理心（推斷某人在想什麼）
  • 慈悲同理心（被驅使去幫助）

在工程團隊中，認知型同理心承擔大部分工作：它預測誤解發生的位置。

出錯時，誘惑是使用「你」訊息，例如「你總是遲交圖紙」。它指派責任並引發防禦。「我」訊息描述行為、感受和具體影響，並留給對方行動的空間。

「我」訊息
When [behaviour], I feel [feeling] because [impact].
描述行為，而非人的性格

03團隊經歷階段

團隊很少透過宣布就變得高效。它們經歷可識別的階段，而領導者的工作在每個階段都會改變。

起初人們彬彬有禮。隨後出現分歧，這是正常的：角色、標準和權限必須協商。只有這樣，共享習慣才能穩定下來。

實際教訓是預期低谷。第三週爭論的團隊，往往比保持和諧、從不檢驗想法的團隊更健康。

團隊階段與領導重點
階段表現領導重點
形成期禮貌，角色不清設定目的和基本規則
風暴期角色摩擦浮現衝突，設定決策規則
規範期信任和共享習慣移交責任
表現期自我管理交付保護專注，消除障礙
解散期收尾回顧和表彰

04角色與社會性懈怠

一群人不自動成為團隊。當每個人都有清晰、獨特的貢獻，且所有人都能看到誰在做什麼時，團隊才能運作。

當責任模糊時，社會性懈怠就會出現：個人減少努力，因為他們的工作與成果之間的聯繫不可見。

  • 為每項任務指定一位具名負責人和可見的狀態。
  • 使貢獻可被審查。
  • 輪換挑戰者角色，使分歧成為責任而非風險。

沒有心理安全感——即提出問題不會受罰的共享信念——這一切都無法維持。

05衝突與回饋

關於工作的衝突往往有建設性；關於人的衝突則有腐蝕性。目標不是消除分歧，而是讓分歧基於證據和後果。

建設性回饋描述發生了什麼、產生了什麼影響以及如何改進，不帶標籤。SBI模式使其可觀察：情境、行為、影響。

「在昨天的簡報中沒有提到堆放位置，所以工人去了錯誤的區域」是個人可以改變的事情。「你粗心大意」則不是。時機與措辭同樣重要：在事件附近、私下給予的回饋會被聽取；留到年度評核的回饋則是判決。

SBI 回饋
Situation + Behaviour + Impact + next step
僅限可觀察的事實，不帶標籤

06無頭銜的領導

情境領導根據人員和任務匹配指導與支持的程度：新任務需要明確指示，熟悉任務需要授權。

變革型領導透過目的和榜樣運作；交易型領導透過明確交換運作。大多數領導者混合兩者。

工程師經常在沒有權限的情況下領導——協調顧問、催促分包商、說服客戶。影響力則依賴於可靠性、準備以及用對方的語言解釋決策的能力。這就是為什麼領導與溝通難以分開。

07任務角色與關係角色

團隊需要兩種貢獻：

  • 任務角色推動工作：組織者構建它，挑戰者檢驗它，完成者落實它。
  • 關係角色維持人員運作：鼓勵者、調解者、注意到沉默同事並邀請他們參與的成員。

一個人可以同時承擔兩者，但沒有團隊能僅靠一種類型生存。只有任務角色而沒有關係角色，會產生一個在壓力下分裂的能幹團隊；反之，則產生一個永遠無法完成的友好團隊。

注意哪些角色缺失，並有意識地採用它們。

角色平衡
Task roles (organiser · challenger · finisher) + Relationship roles (encourager · harmoniser · gatekeeper)
健康的團隊兼具兩者

08能決策的會議

沒有決策的會議是討論，而團隊有太多這樣的討論。

  • 事先發送議程；它列明目的、事項及每項的負責人。
  • 指定主席、計時員和記錄員。
  • 在第一項之前同意決策規則——共識、多數或主席決定。
  • 每項以決策結束，每個決策都有負責人和日期。

會議記錄記錄這兩個事實，而非意見的逐字記錄。沒有負責人的決策是建議；沒有日期的決策是願望。

決策記錄
Decision = Option chosen + Owner + Deadline
寫入會議記錄並在一天內傳閱

09激勵與授權

當工作有意義、進展可見、貢獻被認可時，人們會保持投入。激勵與其說是演講，不如說是消除障礙——不明確的範圍、缺失的工具、不可見的功勞——這些障礙會消耗努力。

授權是移交任務，同時賦予決策權和恢復的支持。說明結果，而非方法；同意檢查點；並進行匯報，以便下一次授權可以更大。

授權工作但保留每個決策不是授權——而是排隊。

授權包
Outcome + Authority + Support + Checkpoint
說明結果，而非方法

10群體決策與群體思維

群體可能比其成員單獨決策更差。群體思維是追求一致而壓制懷疑的驅動力：團隊獎勵共識、壓制批評並忽視外部警告。它表現為過度自信、刻板印象化外部人員以及自封的壞消息審查者。

用結構來對抗它：

  • 在辯論前指定一名魔鬼代言人
  • 在討論前進行一輪沉默的書面意見
  • 邀請外部人士檢驗計劃

目標不是無休止的分歧，而是經過真正挑戰的決策。

群體思維的危險信號 一致來得可疑地快、自我審查（「我不會提出來，大家都同意」）以及未經審查就否定外部批評。

計算示例

與隊友展開困難對話

一位隊友錯過了共同分析的兩個承諾截止日期。下一個任務一週後到期，團隊其他成員正在等待。起草一段對話的開場，要誠實、具體，並可能保持團隊運作。

  1. 寫下可觀察的事實，包括日期和交付物，不詮釋動機。
  2. 具體說明影響：下游任務被延遲，兩人在等待期間被重新部署。
  3. 使用「我」訊息表達你的擔憂，然後在提出任何建議前問一個開放式問題。
  4. 同意一項具體改變、一個檢查點，以及如果延誤會發生什麼——然後記錄下來。
Answer「我」訊息的開場：「當兩個分析部分在約定日期之後才到達時，我無法開始比較，兩人在等待期間被重新部署。我想了解是什麼阻礙了進展。我們能否同意剩餘部分在週四前完成，中午檢查，如果延誤則有B計劃？」

應試方法

  • 描述行為和影響而非意圖；意圖不可見，爭論意圖會浪費對話。
  • 在開處方前指明團隊所處階段——風暴期的團隊需要決策規則，而非更多鼓勵。
  • 在案例題中，診斷溝通失敗時區分個人、團隊和系統。
  • 私下且在事件附近給予回饋；公開糾正通常產生防禦，而非學習。
  • 在關於失敗團隊的案例中，同時指出任務差距和關係差距——大多數答案只停留在任務上。

先作答，再查看解釋。錯誤答案比熟悉的一頁更有用。

Q01在形成-風暴-規範-表現的序列中，角色和標準受到爭議的階段是：

解釋風暴期是可預見的摩擦期，角色、標準和權限在此期間協商。

Q02哪個句子是「我」訊息而非「你」訊息？

解釋它指明行為、說話者的感受和具體影響，而不評判個人。

Q03社會性懈怠最可能發生在：

解釋當努力不可見時，責任分散，一些成員貢獻較少。

Q04一個團隊有強大的規劃者和完成者，但會議讓兩名成員沉默和不滿。最可能缺失的元素是：

解釋工作有進展但人員沒有被承載——缺少鼓勵者或守門人角色。

Q05哪種做法最直接對抗群體思維？

解釋指定的挑戰者使分歧成為責任，因此在決策前疑慮得以表達。
