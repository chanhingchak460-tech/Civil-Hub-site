How models learn patterns from data, and how to tell whether one is any good. It covers regression, classification, validation, the metrics that match a real question, overfitting, neural networks and the ethics of deploying a model.

01Learning is fitting a function

Machine learning fits a function from examples instead of writing rules by hand.

  • Supervised learning: each example carries a label; regression predicts a number, classification a category.
  • Unsupervised methods look for structure without labels — clustering, dimension reduction.
  • Reinforcement learning learns actions from reward.

The estimate is only as good as the sample: biased or unrepresentative data produce a confident model that is wrong in deployment.

02Regression and classification

Linear regression fits a straight line to a numeric outcome by least squares; the error term collects what the line misses. For a yes/no decision, logistic regression passes a linear score through the sigmoid to give a probability between 0 and 1.

The score defines a boundary at zero; the output is a probability, not a verdict. A threshold converts it into a class, trading false positives against false negatives.

Linear regression
\[y = \beta_0 + \beta_1 x + \varepsilon\]
ε is the part of y the line does not explain
Logistic (sigmoid) model
\[p = \frac{1}{1 + e^{-s}}, \quad s = w \cdot x + b\]
p is a probability; the class comes from a chosen threshold

03Training: loss and gradients

Training chooses parameters that make predictions close to the labels.

  • A loss function measures the gap — squared error for regression, cross-entropy for classification.
  • Gradient descent nudges each weight against the gradient of the loss.
  • The learning rate is the critical choice: too small and training crawls, too large and the loss jumps around or diverges.
  • Mini-batches trade noisy gradients for speed; one pass over the data is an epoch.
Gradient descent update
\[w \leftarrow w - \eta \frac{\partial L}{\partial w}\]
η is the learning rate; each step is opposite to the gradient

04Validation and leakage

A model scored on the data it learned from is marking its own homework. Split into training, validation and test sets; fit on training, choose hyperparameters on validation, and touch the test set once at the end. k-fold cross-validation rotates the validation fold so the estimate uses every row.

Leakage is the silent killer: scaling before the split, duplicate records across sets, or features recorded after the outcome. Time-ordered data must be split by time, not at random.

Stratified split and fit
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2, stratify=y) model.fit(X_tr, y_tr) score = model.score(X_te, y_te)
stratify keeps the class balance in both parts; fit only on the training rows

05Metrics that match the question

Accuracy is the first metric and often the wrong one. With 1,000 cases of which 60 are positive, a model that always says no scores 94% accuracy and catches nothing.

  • A confusion matrix separates true positives, false positives, false negatives and true negatives, from which precision and recall follow.
  • F1 balances the two, while ROC-AUC measures ranking across all thresholds.
  • Regression metrics differ: RMSE penalises large errors, MAE keeps the original units, and R² is the variation explained.
Precision and recall
\[\mathrm{precision} = \frac{TP}{TP + FP}, \quad \mathrm{recall} = \frac{TP}{TP + FN}\]
precision punishes false alarms; recall punishes missed positives
F1 score
\[F_1 = \frac{2 \cdot \mathrm{precision} \cdot \mathrm{recall}}{\mathrm{precision} + \mathrm{recall}}\]
the harmonic mean, so a poor value on either side drags it down
Classification metrics and the trap in each one
MetricWhat it answersTrap if used alone
AccuracyShare of all cases correctDominated by the majority class
PrecisionOf those flagged, how many were rightIgnores missed positives
RecallOf real positives, how many were foundIgnores false alarms
F1Balance of the twoHides the cost of each error type
ROC-AUCRanking quality across thresholdsNo decision at a chosen threshold

06Overfitting and regularisation

Overfitting is learning the training set rather than the pattern: training error keeps falling while validation error rises. It comes from a model that is too flexible for the amount of data.

The cure is more data, a simpler model, or regularisation that adds a penalty for large weights. Dropout, early stopping and augmentation are other forms of restraint. Underfitting is the opposite failure, and no amount of tuning fixes a model that cannot express the pattern.

Regularised loss (L2)
\[L_{\mathrm{reg}} = L + \lambda \sum w^2\]
λ controls how strongly large weights are punished

07Neural networks

A neural network stacks layers of weighted sums and non-linear activations; depth lets it represent interactions that a linear model cannot. ReLU is the common activation, and backpropagation computes the gradients that gradient descent needs.

Convolutional layers exploit local structure in images, and sequence models handle ordered data. Networks need more data and compute than classical models, and they remain hard to interpret, which matters when a decision affects a person.

08Ethics and deployment

A good test score is not permission to deploy. Ask who is represented in the training data, whether errors fall unevenly on groups, and who can challenge a decision.

Distribution shift means the world moves after training, so performance decays and must be monitored. Document the data, the metric and the limits, and keep a human in the loop where the cost of error is high. A model is a component in a system, and the system carries the responsibility.

09Tree ensembles: the tabular champion

A decision tree splits the data on simple threshold questions and predicts the average or majority in the leaves. Trees overfit easily, so ensembles pool many of them: random forests grow trees on bootstrapped samples with random feature subsets, while gradient boosting builds trees sequentially, each one fitted to the errors of the ensemble so far.

For tabular data — the tables of measurements common in engineering — boosted trees such as XGBoost and LightGBM are usually the first model to try: they handle missing values and mixed units, need little tuning, and beat deep networks on most small and medium tables. The main knobs are the learning rate, tree depth and number of trees; a small learning rate with many trees is the default recipe.

Boosting ensemble
\[\hat{y} = \sum_{m=1}^{M} \eta \, h_m(x)\]
each tree h_m is fitted to the remaining errors; η is the learning rate

10Hyperparameter tuning done honestly

Hyperparameters — depth, learning rate, regularisation strength — are chosen by trial, and each trial spends information from the data it is scored on. Tune on the validation fold, not the test set: using the test set repeatedly turns it into part of the training procedure and its final score stops being an unbiased estimate.

  • Cross-validation is the workhorse: split the training data into folds, train on all but one, validate on the held-out fold and rotate.
  • With imbalanced classes, use stratified folds so each fold keeps the same class proportions.
  • Report the mean and spread of the fold scores rather than the best one.
  • When a model's result matters, wrap the whole search in an outer loop of nested cross-validation.
Stratified k-fold search
skf = StratifiedKFold(n_splits=5, shuffle=True) grid = GridSearchCV(pipe, param_grid, cv=skf, scoring='f1') grid.fit(X_train, y_train) final_score = grid.score(X_test, y_test)
tuning uses folds of the training data only; the test set is touched once
The test set is spent on contact Every decision made after looking at the test set — a threshold, a feature, a model family — makes that score optimistic; budget exactly one look.

11Unsupervised learning: clustering and PCA

Without labels, models look for structure.

  • k-means clustering assigns each point to the nearest centroid and recomputes the centroids until the assignment stops changing; it minimises the within-cluster squared distance, so the number of clusters k is a modelling choice, and an elbow plot of the objective against k suggests where adding clusters stops paying.
  • Principal component analysis finds the directions of largest variance and projects the data onto them, compressing many correlated columns into a few components. The share of variance kept measures what the projection preserves; drop components when the cumulative share plateaus.

Clustering results are exploratory — validate them against a downstream purpose rather than quoting a score.

k-means objective
\[\mathrm{SSE} = \sum_j \sum_{x \in C_j} \lVert x - \mu_j \rVert^2\]
the sum of squared distances from each point to its cluster centroid

Key terms

Supervised learning
Learning a mapping from inputs to known labels, covering regression for numbers and classification for categories.
Overfitting
Fitting the training data so closely that the model performs poorly on new data.
Precision
The share of flagged cases that are genuinely positive, TP divided by TP plus FP.
Recall
The share of genuine positives that the model found, TP divided by TP plus FN.
Cross-validation
Repeatedly splitting the training data so each part serves once as validation, giving a more stable performance estimate.
Regularisation
A penalty on model complexity or large weights that reduces overfitting.
Distribution shift
A change in the data seen in deployment compared with the training data, causing performance to decay.
Ensemble learning
Combining many base models, such as trees, to reduce variance or bias and improve predictions.
Clustering
Grouping unlabelled data so that points in the same group are more similar to each other than to points in other groups.
Worked example

Reading a screening model's confusion matrix

A model screens 1,000 structural inspections. In reality 60 components are defective. The model flags 50 components; 40 of those are truly defective, 10 are not, and 20 defective components are missed. Compute accuracy, precision, recall and F1, and say which metric should guide the decision.

  1. Label the counts: TP = 40, FP = 10, FN = 20, TN = 930.
  2. Accuracy = (TP + TN) / total = (40 + 930) / 1000 = 0.97.
  3. Precision = TP / (TP + FP) = 40 / 50 = 0.80.
  4. Recall = TP / (TP + FN) = 40 / 60 = 0.667.
  5. F1 = 2 × 0.80 × 0.667 / (0.80 + 0.667) = 0.727.
AnswerAccuracy is 97%, precision 0.80, recall 0.67 and F1 0.73. The headline accuracy hides that one in three defects is missed, so recall should drive the decision: lower the threshold to find more defects, accepting more false alarms, and report both metrics together.

Exam method

  • Draw the confusion matrix before computing any classification metric; the arithmetic is easier and errors are visible.
  • Name the metric the question actually needs, and explain in one sentence why accuracy would mislead.
  • If a validation score looks unusually good, check for leakage before reporting it as a result.
  • For tabular engineering data, fit a gradient-boosted tree before a neural network; it is usually stronger and needs less tuning.

Q01A model reports 97% accuracy on a dataset where only 3% of cases are positive. The main risk is that:

WhyPredicting the majority class everywhere gives high accuracy while finding no positives, so precision and recall are needed.

Q02Which dataset should be used to give the final, unbiased performance estimate?

WhyTuning on validation leaks information; the held-out test set gives the only clean estimate.

Q03Training loss keeps falling while validation loss rises. This indicates:

WhyThe model is memorising the training data and losing generalisation, which is the signature of overfitting.

Q04A gradient descent learning rate that is far too large usually causes:

WhyEach step overshoots the minimum, so the loss jumps or grows instead of settling.

Q05Gradient boosting differs from a random forest mainly because:

WhyBoosting grows trees sequentially, each correcting the residuals left by the previous ensemble, while a forest grows trees independently.

Q06k-means clustering assigns points to clusters by:

WhyEach iteration assigns every point to its nearest centroid, then moves the centroids to the mean of their assigned points.
