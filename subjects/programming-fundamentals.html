A first course in thinking like a program: storing values, steering decisions, repeating work, packaging logic into functions, and moving data through files. These habits carry into every later computing subject.

Your progress is stored only in this browser.

01Values, names and types

A variable is a name bound to an object, not a labelled box of fixed size. Python decides the type at run time: int for whole numbers, float for decimals, str for text and bool for True or False. Use type(x) when unsure, and convert deliberately with int(), float() and str().

The operator you choose changes the result. / always produces a float, // floors to an integer and % gives the remainder, which is the basis of many digit and parity tricks.

Floating-point values are binary approximations, so test 0.1 + 0.2 and you will not get exactly 0.3; compare with a tolerance instead of equality.

Quotient and remainder 
q, r = divmod(n, 10)
splits off the last digit

02Input, output and formatting

input() always hands back a string, even when the user types digits. Convert before doing arithmetic, otherwise "7" + 1 raises a TypeError rather than giving 8.

Formatting is part of the answer. Prompts and outputs often have to match exactly, so build them with f-strings: f"{day:02d}" zero-pads a day, and f"{total:.4f}" keeps four decimal places.

A tidy program separates the prompt, the calculation and the display; mixing them makes debugging and marking harder.

Reading a number 
n = int(input("Please enter a number: "))
input returns text; convert before arithmetic

03Decisions with if, elif and else

Conditionals choose a path, and every condition is just an expression that evaluates to true or false. Order the branches from most specific to most general, and add a final else only when every remaining case belongs there.

Watch the classic mistakes:
- = assigns while == compares
- and binds more tightly than or
- a test such as if name: is true for any non-empty string, which is often more than you intended

Write the intended cases as comments first, then code them — that small habit removes most logic errors before they appear.

04Loops and the accumulator pattern

A for loop walks over a sequence; a while loop repeats until a condition fails. Choose for when the number of items is known and while when it is not, and make sure the while condition can actually become false — a loop variable that never changes gives an infinite loop.

The most reusable pattern in early programming is the accumulator: start a total at zero, add each item inside the loop, report after the loop. The same shape counts, sums, filters and searches.

Keep the update line explicit so a reader can see exactly what changes and when.

Accumulating a running total 
total = total + x
initialise total = 0 before the loop

05Functions and recursion

A function gives a name to a piece of logic, takes parameters and returns a value. Prefer returning a result over printing inside the function: returned values can be tested, reused and composed. Keep each function to one job and name it for what it does.

Recursion solves a problem by calling a smaller version of itself. Every recursive function needs a base case that returns without recursing, plus a recursive step that moves towards it.

A Fibonacci function is the standard demonstration, but recursion also suits nested structures where a loop would need its own stack.

Recursive Fibonacci
\[\mathrm{fib}(n) = \mathrm{fib}(n - 1) + \mathrm{fib}(n - 2)\]
with base cases fib(1) = fib(2) = 1

06Lists, tuples and dictionaries

A list is an ordered, mutable sequence indexed from zero, so a[0] is the first item and a[-1] the last. Slicing copies a section, while append, sort and remove edit the list in place. Because a list is shared by reference, b = a does not copy it; b = a[:] does.

A tuple is an immutable sequence, useful for fixed groups such as coordinates. A dictionary maps keys to values and is the natural structure for counting, because it can create a key lazily instead of demanding a pre-check.

Nested lists represent matrices: loop over rows first, then over columns.

Counting with a dictionary 
counts[ch] = counts.get(ch, 0) + 1
avoids a separate membership test

07Strings are sequences too

A string behaves like a tuple of characters: it is immutable, indexable and sliceable, so text[2:5] gives the characters at indices 2, 3 and 4, and text[::-1] reverses it.

The predicate methods classify single characters — isalpha(), isdigit(), isspace() — and return booleans you can test inside a loop.

Building output from parts is a recurring pattern: split text into tokens with split(), join them back with '-'.join(tokens), and trim stray whitespace with strip(). Methods return new strings rather than changing the original, so assign the result when you want to keep it.

Classifying characters in a loop
if ch.isdigit(): digits += 1
walk the string once and update a counter per character class

08Nested loops and two-dimensional data

A list of lists represents a grid or matrix: grid[r][c] is the element in row r, column c, and the standard traversal is an outer loop over rows with an inner loop over columns.

The same nesting prints triangular patterns such as Pascal's triangle, where each interior entry is the sum of the two above it.

Matrix multiplication is the exam favourite: the element in row i, column j of the product is the dot product of row i of the first matrix with column j of the second. Test the shapes first — an n×m matrix times an m×p matrix gives n×p — because swapping the indices is the classic silent error.

Pascal's triangle entry
\[T(r,k) = T(r-1,k-1) + T(r-1,k)\]
edges are 1; each interior entry sums the two above it
Matrix multiplication
\[C[i][j] = \sum_{k} A[i][k]\,B[k][j]\]
sum over the shared inner dimension k

09Files and simple data processing

Open a file inside a with block so that it closes even if something fails. Reading gives you lines including the trailing newline, so strip() first and split() second when parsing. Writing is literal: print adds a newline, but file.write() does not, so add "\n" yourself.

Real data is messy. Convert a token to a number only after checking that it looks like one, and skip invalid words rather than crashing.

For tabular data, the csv module or a dataframe library removes a great deal of fragile manual splitting; keep the parsing separate from the reporting so each part can be tested alone.

10Modules, libraries and the bigger toolbox

A module is a file of reusable definitions: import math brings in a library, and math.sqrt(x) calls one function without re-implementing it. The standard library covers randomness, dates and file paths, while third-party packages such as pandas and matplotlib turn tabular data into analysis and charts in a few lines.

Libraries do not remove the fundamentals — you still choose types, loop correctly and validate input. Treat a library call as a black box you can name and test, not as a substitute for knowing what the data means.

When a task forbids a library, it is asking you to demonstrate the underlying logic yourself, so write the loop you would otherwise have imported.

Reading a table with pandas
df = pd.read_csv('counting.csv') df.plot()
the library parses, stores and plots the data; your job is to check the result

11Debugging is a skill, not luck

Read the traceback from the bottom up: the last line names the error, and the line above shows where it happened. Reproduce the failure with the smallest input you can find, then narrow the region by printing values at two points and asking where they first disagree.

Check boundaries deliberately — empty input, a single item and the largest allowed value. Most beginner bugs are off-by-one errors, a missing conversion or a list mutated by the next function.

Write one small test that should pass and rerun it after every change.

Key terms

Variable
A name that refers to an object, whose type is determined at run time rather than declared in advance.
Immutable
An object whose value cannot be changed after creation, such as a string or a tuple.
Accumulator
A variable that collects a result while a loop runs, usually starting from zero or an empty collection.
Recursion
A technique where a function calls itself on a smaller input, stopped by a base case.
Dictionary
A mutable mapping from keys to values, written with braces and read with square brackets.
Traceback
The report Python prints when an error occurs, listing the call stack and the failing line.
Slice
A copy of a contiguous section of a sequence, written with start, stop and optional step indices.
Module
A file of reusable definitions that a program can import and call by name.
Worked example

Tracing a digit-sum function

Trace this function by hand and state what it returns for the call digit_sum(274): def digit_sum(n): total = 0 while n > 0: total = total + n % 10 n = n // 10 return total print(digit_sum(274))

  1. Start: n = 274 and total = 0. The loop test 274 > 0 is true.
  2. First pass: total = 0 + (274 % 10) = 0 + 4 = 4, and n = 274 // 10 = 27.
  3. Second pass: total = 4 + (27 % 10) = 4 + 7 = 11, and n = 27 // 10 = 2.
  4. Third pass: total = 11 + (2 % 10) = 11 + 2 = 13, and n = 2 // 10 = 0.
  5. Loop test: 0 > 0 is false, so the loop stops and the function returns total = 13.
AnswerThe function returns 13. Sanity check: the digits of 274 are 2, 7 and 4, and their sum is 13, which matches the trace.

Exam method

  • Trace loops on paper with one column per variable; do not try to run the code in your head.
  • Convert input to the right type before arithmetic — this is the most common single mark lost.
  • Read error messages from the last line upwards and fix one error at a time.
  • Test the boundary cases: empty input, one item and the maximum allowed value.
  • When a question forbids find() or count(), write the loop yourself: initialise a counter, walk the characters, and update it on the condition.
