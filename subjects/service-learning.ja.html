地域パートナーと実際のプロジェクトに取り組みながら、その活動自体から学ぶ。ニーズ評価、共同設計、実施、誠実な評価、構造化された振り返りを扱い、慈善ではなく相互性を重視する。

01ボランティア以上のもの

サービスラーニングはパートナーと共に行う授業である。学生は通常、学校、慈善団体、住民グループと共に実際の地域プロジェクトに取り組み、振り返りと学習の証拠によって評価されるため、単位が認定される。

ボランティアとの違いは相互性である。地域は求めたものを得て、学生は講義では得られない知識を得る。慈善は人々のために何かをするが、サービスラーニングは人々と共に行う。

02ニーズ評価から始める

聞く前に設計してはならない。ニーズ評価では、誰が影響を受けるか、すでに何を持っているか、何が不足していると本人たちが言っているかを尋ねる。

  • 受け入れてくれるスタッフだけでなく、成果物を使う人々にインタビューする。
  • 文献で読むのではなく、現場を歩く。
  • アセットベースの視点を持つ。学校は設備に欠けても、ホール、時間割、生徒をよく知る教師がいる。
  • パートナーが何を求めたかを記録し、課題定義を自分たちだけでなく相手のものにする。

03上からの提供ではなく共同設計

参加型設計では、ユーザーに最後の意見聴取ではなく実際の決定権を与える。

  • 早期に安価に試作する。紙模型、授業案の草稿、ウォークスルーなど。人は抽象的な提案よりも具体的なものにはるかによく反応する。
  • 言語、読解レベル、移動、費用、時間の障壁に注意する。
  • ワークショップ開始前に、固定する点と開かれた点を合意し、グループが実際にどこに力を持つかを知らせる。

04現実の制約の中で実施する

サービスプロジェクトもプロジェクトである。範囲、スケジュール、予算、リスクがある。パートナーには暦、規則、忙しいスタッフがおり、学校の試験期間を無視した計画は失敗する。

  • 子どもや脆弱な成人と関わる際はセーフガーディングと同意を計画する。
  • 最初のセッション前に保険と現場の安全を確認する。
  • 自分たちが去っても活動が続くよう能力を構築する。手順書、教材、連絡先の名前を残す。

05振り返りこそが学習

振り返りは出来事の日記ではない。経験を理論と自分の実践に結びつける構造化された思考である。

ギブス・サイクルは一つの道筋を示す。状況を描写し、感情を名づけ、うまくいったことを評価し、なぜかを分析し、次はどうするかを結論づけ、行動を約束する。優れた振り返りは具体的で、困難を認め、理解の変化を示す。出来事が証拠であり、一般的な主張は証拠にならない。

ギブス振り返りサイクル
Description → Feelings → Evaluation → Analysis → Conclusion → Action plan
最後の段階は要約ではなく約束である

06影響を誠実に評価する

成果物は数えられる。ワークショップを実施した、模型を作ったなど。アウトカムは知識、行動、自信の変化であり、インパクトはより長期的な違いである。

  • パートナーに成功をどう判断するかを尋ねる。
  • 印象だけではなく、短い前後比較の指標を使う。
  • うまくいかなかったこと、取り残された人、変えるべきことを報告する。

誠実な評価は、飾られた成功談よりもパートナーの役に立つ。

インパクトの連鎖

チームが作って面白いと思ったものではない

07手早い振り返りの枠組み

ギブスだけが唯一の方法ではない。What? So what? Now what? の枠組みは振り返りを三つの動きに圧縮する。出来事を描写し、なぜ重要で何を教えるかを説明し、変化を約束する。短い振り返りやセッション後の簡単な振り返りに適している。

どのモデルでも証拠の基準は同じである。良い振り返りは一つの出来事を名づけ、概念に結びつけ、変わった意図で終わる。「生徒たちは静かだった」は日記である。「生徒たちは静かだったが、手を動かす工作に切り替えると静かでなくなった。これは参加が活動に伴うことを示すので、次回は話を減らして計画する」は振り返りである。

What? So what? Now what?
What happened → So what (why it matters) → Now what (what changes)
三つの動き、一つの出来事

08倫理、同意、位置性

あなたは大学のバッジを持つ外部者として来るので、力の差に気づくこと。位置性とは、プロジェクトにおける自分が誰か（背景、資源、前提）と、それが見えるものをどう形作るかを正直に説明することである。地域の人々は自分の生活の専門家であり、対象ではなく共同所有者として扱う。

  • 写真を撮ったり公開したりする前に、特に子どもの場合は書面による許可を得る。
  • 参加者はいつでも撤退できるようにする。
  • 個人やグループを特定せずに調査結果を報告する。
  • パートナーが言ったことを書き、言ってほしかったことを書かない。
同意は任意ではない 書面による同意なしに参加者（特に未成年者）を撮影したり名前を出したりすることは、信頼とセーフガーディングの規則の両方を破る。最初のセッションだけでなく、毎回確認する。

09適応するセッション：リハーサルとプランB

すべてのセッションには試行が必要である。活動の試作品を作り、時間を計る。チームが90分かかる模型は、初めての教室ではその倍かかる。指示を声に出してリハーサルする。グループを失う最速の方法は、誰も理解できない課題である。

次に代替案を準備する。壊れるもののための予備材料、異なる能力向けの簡単版と難しい版、一つの遅い手順が次の活動を食いつぶさないための時間的余裕。プランBは悲観主義ではなく、来てくれた人への敬意である。

セッション計画
Objective + Materials + Timing + Plan B
目的を最初に書き、それに役立たないものは削る

10引き継ぎと持続可能性

プロジェクトは終わるが、地域は残る。引き継ぎは、パートナーがあなたなしで続けられるようにする。書面の手順、通常使用に耐える教材、パートナー側で作業を理解する担当者の名前。彼らが主導し、あなたが見学するセッションを一度行う。

持続可能性はメンテナンスについての正直さでもある。毎週の手入れが必要なセンサーや庭は、誰かが所有しなければ負担になる。去ってから数か月後にパートナーとフォローアップ測定を合意し、最終報告書が約束されたことではなく実際に続いたことを言えるようにする。

引き継ぎパッケージ
Instructions + Materials + Named owner + Follow-up check
成果物だけでなく能力を残す

Key terms

相互性
地域と学生がそれぞれ相手に必要なものを得る双方向の交換。
ニーズ評価
対応を設計する前に、地域が何を持ち、何に欠け、何を求めているかを見つける構造化されたプロセス。
参加型設計
完成した提案を提示するのではなく、ユーザーを意思決定者として共に設計すること。
アセットベースのアプローチ
地域の欠点からではなく、すでに持っている強みと資源から始めること。
セーフガーディング
活動中に子どもや脆弱な成人を害から守る方針と実践。
省察的実践
将来の行動を改善するために、経験について意図的かつ構造的に考えること。
位置性
プロジェクトにおける自分が誰か（背景、資源、前提）と、それが見えるものをどう形作るかを正直に説明すること。
引き継ぎ
チームなしで作業を続けられるよう、手順、教材、担当者の名前をパートナーに残すこと。
Worked example

依頼をプロジェクト課題定義に変える

パートナーの学校が学生チームに「生徒に持続可能性について教えてほしい」と依頼した。チームには6週間と少額の予算がある。この依頼を、評価可能な成果を持つ実行可能なプロジェクトにどう変えるべきか。

  1. パートナーにどのような問題を見ているかを尋ねる。おそらく生徒が話題を抽象的だと感じているのであり、教えられたことがないのではない。
  2. すでに存在するもの（授業、クラブ、屋上庭園）を確認し、重複ではなく資産の上にプロジェクトを築く。
  3. 生徒が自分の言葉でグリーンシティの特徴を3つ説明するなど、具体的で観察可能な成果をパートナーと合意する。
  4. 限られた時間と材料でその成果を試す活動を一つ設計し、まず小グループで試作する。
  5. 成功をどう判断するかを合意し、結果を授業の概念に結びつける振り返りを書く。
Answer曖昧な依頼は、名前のある成果、合意された対象者、単一の測定可能な活動、パートナーが定義した成功基準を持つ課題定義になる。振り返りは活動を列挙するのではなく、その成果に対する学習を証拠づけられる。

Exam method

  • 解決策を述べる前にパートナーのニーズを名づける。評価者はまず聞いた証拠を探す。
  • 各振り返りはプロジェクト全体の要約ではなく、具体的な出来事のある一つの転換点に焦点を当てる。
  • 評価の問いではアウトプットとアウトカムを分ける。それらは異なる基準で判断される。
  • 倫理の問いでは、法的に許されることとパートナーが尊重と考えることを分ける。同意と匿名性が最初の点数を運ぶ。
