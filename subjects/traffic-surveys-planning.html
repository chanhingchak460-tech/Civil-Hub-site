How movement is measured and then predicted. It covers classified counts and origin–destination surveys, sampling and expansion, the four-step demand model, network assignment and the land-use feedback that decides whether a forecast is realistic.

01Planning is a chain of evidence

Transport planning predicts how many people will move, where, by which mode and along which links, so that infrastructure and services can be sized before demand arrives. The classic four-step model runs: trip generation, trip distribution, mode choice and assignment.

Each step needs data of a different kind, and an error at the start is not repaired by a clever model at the end. Strategic plans look decades ahead, tactical plans a few years, and operational plans a season.

02Counting and interviewing

The basic tool is the classified count, which records volume by vehicle type and direction over a period. Counts can be manual, temporary automatic (tubes, loops, radar) or permanent; short counts are expanded to a typical day using factors.

Origin–destination surveys ask where trips start and end: roadside interviews, number-plate matching, GPS traces or mobile network data. Speed surveys measure spot speed or journey time, and parking surveys record accumulation and duration.

03Sampling, expansion and error

No survey counts everything. A sample is expanded to the population, so the expansion factor carries its sampling error with it. Sampling error falls with the square root of sample size, so quadrupling the sample halves it.

Coverage bias is worse than random error — counting only weekday peaks, or only drivers who stop for an interview, measures a selected group. Neutral months and neutral days matter, and public holidays are excluded.

Sample size for a proportion
\[n = \frac{z^2 p (1 - p)}{e^2}\]
z ≈ 1.96 for 95% confidence, p the expected proportion, e the margin of error

04Trip generation and the O–D matrix

Trip generation estimates how many trips a household or development produces, from survey data by household size, income and car ownership, or from regression. The output is a trip matrix: rows are origins, columns are destinations, and the diagonal holds intrazonal trips.

Matrices are expanded from the sample to the population and balanced so row and column totals agree with control totals. Poor zoning — too coarse, or in the wrong place — distorts everything downstream.

05Trip generation models

Trip generation is estimated either by category analysis — average trip rates per household or person in each size or income class — or by regression, which fits trips against household characteristics. A typical model regresses daily trips on household size and car ownership, giving a constant plus a rate per explanatory variable.

The coefficients are not facts; they are fitted to one survey and inherit its bias. A small, unrepresentative sample produces rates that look precise and are systematically wrong. Compare fitted rates against a large citywide travel survey before using them, and keep the units — trips per household per day — attached to every coefficient.

Linear trip generation model
\[T = a + b_1 X_1 + b_2 X_2 + \dots\]
T trips per household or person; X the explanatory variables; coefficients fitted by least squares
Category trip rate
\[r = \frac{T}{H}\]
T trips from the category sample, H households or persons; applied as T_i = r × H_i
A precise fit is not an accurate one Small and homogeneous samples fit regression lines beautifully while misrepresenting the population — always validate trip rates against a large travel survey before using them in a forecast.

06Distribution and mode choice

Trip distribution decides where generated trips go. The gravity model allocates trips to destinations in proportion to their attractiveness and inversely to the cost of reaching them, with a deterrence function calibrated against observed travel.

Mode choice then divides each flow among car, public transport and walking using generalised cost — time, fare, waiting, comfort and reliability combined. A logit model turns the utility of each option into a probability, so a small cost change produces a gradual shift rather than an all-or-nothing switch.

Gravity model
\[T_{ij} = \frac{P_i A_j f(c_{ij})}{\sum_k A_k f(c_{ik})}\]
T_ij trips from i to j, P_i production, A_j attraction, f a deterrence function of cost c
Logit mode share
\[P_m = \frac{e^{U_m}}{\sum_k e^{U_k}}\]
U is the utility of a mode, often negative generalised cost

07Assignment and network equilibrium

Assignment loads the matrix onto a network of nodes, links, zones and centroid connectors. Travel time rises with flow, so a volume–delay function such as the BPR curve is applied to each link.

All-or-nothing assignment ignores congestion and overloads the shortest route; equilibrium assignment spreads flow until no driver can improve by switching route, which is Wardrop's user equilibrium. Software such as SATURN or EMME iterates towards that state, and the result must be checked against counts.

BPR volume–delay function
\[t = t_0 \left[1 + \alpha \left(\frac{v}{c}\right)^\beta\right]\]
t₀ free-flow time, v flow, c capacity; α ≈ 0.15 and β ≈ 4 are common defaults

08Building the assignment network

Assignment software needs a coded network before it needs mathematics. Zones are linked by centroid connectors to nodes, nodes join as links with free-flow speed, capacity and length, and the trip matrix is attached to the zones.

Each element is a place where a coding error hides: a reversed one-way, a missing connector or a capacity of zero silently corrupts the answer. The workflow is the discipline: build the network, compile it, load the matrix, run the assignment, then check the results against counts and the GEH statistic before believing them. Scheme options are tested the same way — code the option, assign, and compare against the base case rather than against intuition.

Assignment workflow
code network → compile → load matrix → assign → validate against counts
every stage needs checking; a result is only as good as the coding behind it

09Parking surveys and turnover

Parking surveys measure accumulation — the number of vehicles parked at a time — and duration, the length of each stay. Accumulation changes as vehicles arrive and leave, and the peak accumulation sizes the parking supply. Duration separates short-stay shoppers from long-stay commuters, and the two groups need different policies.

Turnover is the number of different vehicles served by one space in a period: a high-turnover short-stay space serves many users, a low-turnover one serves one commuter all day. Enforcement, pricing and time limits all target the gap between the two.

Parking accumulation
\[A_t = A_{t-1} + \mathrm{arrivals}_t - \mathrm{departures}_t\]
tracked through the survey period to find the peak
Parking turnover
\[U = \frac{V}{S}\]
V vehicles parked over the period, S spaces; e.g. 400 vehicles on 100 spaces is a turnover of 4

10Land use, validation and judgement

Transport and land use shape each other. Faster links raise accessibility, which attracts development, which generates traffic: induced demand. A model that ignores this feedback flatters a road scheme by assuming fixed demand.

Validation compares modelled flows with counts, often using the GEH statistic, which is insensitive to scale and easy to apply. Planners also report uncertainty, test scenarios and ask who bears the cost of being wrong, because a plan is an argument about the future, not a measurement of it.

GEH statistic
\[\mathrm{GEH} = \sqrt{\frac{2 (M - C)^2}{M + C}}\]
M modelled flow, C counted flow; below 5 is good, above 10 signals a problem

Key terms

Classified count
A traffic count that records volume by vehicle type, direction and time period.
O–D matrix
A table of trips between origin zones and destination zones.
Expansion factor
The multiplier that scales a sample count up to the population or to a typical day.
BPR function
A volume–delay relationship giving link travel time as a function of the flow-to-capacity ratio.
Gravity model
A trip distribution model in which flows grow with origin production and destination attraction and fall with travel cost.
GEH statistic
A scale-free measure of the difference between modelled and counted flows, with 5 as a common acceptance threshold.
Trip rate
The average number of trips per household, person or vehicle, used in category analysis to expand zonal totals.
Parking turnover
The number of vehicles served by one parking space during a period, the ratio of parked volume to spaces.
Worked example

Checking a modelled link against a count

A link has a free-flow time of 5.0 minutes and a capacity of 5,000 veh/h. The model assigns 4,500 veh/h to it, using α = 0.15 and β = 4. The observed count is 3,800 veh/h. Find the modelled travel time and the GEH statistic, then judge the model for this link.

  1. Compute v/c = 4,500 / 5,000 = 0.9, so (v/c)^4 = 0.6561.
  2. Apply BPR: t = 5.0 × (1 + 0.15 × 0.6561) = 5.0 × 1.0984 = 5.49 minutes.
  3. GEH = √[2 × (4,500 − 3,800)² / (4,500 + 3,800)] = √(980,000 / 8,300) = √118.1 = 10.9.
  4. Compare with the usual bands: below 5 acceptable, 5 to 10 needs investigation, above 10 indicates a poor fit.
  5. Investigate zone loading, centroid connectors and the network coding near the link before using the forecast.
AnswerThe modelled travel time is 5.49 min and GEH = 10.9, so the link fails the usual validation band. The model over-assigns flow here, and the cause should be found before the scheme is evaluated.

Exam method

  • State the survey's purpose before its method: an O–D question cannot be answered by a classified count, however accurate.
  • In expansion and sampling questions, write the formula, substitute, and comment on coverage bias — random error is rarely the whole story.
  • For network questions, check v/c and the volume–delay function before discussing equilibrium, because the equilibrium result depends on the link curves.
  • State the units of every trip-generation coefficient — trips per household per day — because marks are lost switching between daily, weekly and annual rates.

Q01Which survey directly measures where trips begin and end?

WhyOnly methods that track or ask individual trips give an origin–destination pattern.

Q02In the BPR function, travel time rises with flow because:

WhyThe term (v/c)^β grows as flow approaches capacity, raising the delay above free-flow time.

Q03A GEH value of 12 between modelled and observed flow usually means:

WhyValues above 10 are normally treated as a poor fit and prompt a check of the model and data.

Q04Quadrupling a sample size reduces the standard sampling error by a factor of about:

WhyError scales with 1/√n, so four times the sample halves the error.

Q05A regression trip generation model gives T = 1.2 + 2.4 H, where H is household size in persons. A zone of 300 households averaging 3.1 persons generates about:

WhyPer household: 1.2 + 2.4 × 3.1 = 8.64 trips, and 300 households give about 2 590 trips in total.

Q06A car park of 80 spaces serves 240 vehicles between 07:00 and 19:00. Its turnover is:

WhyTurnover is parked volume divided by spaces: 240 / 80 = 3 vehicles per space in the period.
